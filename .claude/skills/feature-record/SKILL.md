# 機能の記録を書く

機能ごとに1つ、`docs/outbox/F-NN-<題>.md` を書く。`NN` は `docs/features.md` の番号、`<題>` はその機能の短い名前（英小文字とハイフン）。例: `F-01-chat.md`。

記録は、後でブログにするときに書き足さずに済むように書く。公開できる文体である必要はない。

## 手順

1. [template.md](template.md) を写し、`docs/outbox/F-NN-<題>.md` を作る
2. 機能の進め方の段ごとに、分かったときに埋める。終わってからまとめて思い出して書かない
   - 仕様を人が承認したら: 要件。仕様は `docs/features/f-NN-<機能名>/spec.md` に書き、記録からはそれを指す
   - 実装したら: 実装の要点・読む順の案内（案）。実際に実装された仕様と仕組みは `docs/features/f-NN-<機能名>/implementation.md` に書く
   - 人が読んだら: 読む順の案内（人が読んだ順と理由）・人が読んで分かったこと・分からなかったこと
   - 人が試したら: 試し方・結果。数値は走行の記録 `traces/` から取り、`docs/features/f-NN-<機能名>/measurements.md` に書いて、記録からはそれを指す
   - 最後に: Claude Code との違い・残った課題

   docs/features/ の下は公開する文書で、書き方は `.claude/rules/docs.md` に従う。outbox の記録は公開しない（人が読んで分かったこと・分からなかったことなど）
3. 書いたあとで直すときは、消さずに追記する（末尾に「追記（日付）」の節を足す）
4. 書き終えたら、上流のセッションに SendMessage で「outbox に書いた」と知らせる。中身は SendMessage に書かない

## 書き方

- 数値は、どの走行の記録から取ったか（ファイル名）を添える
- 結果には、期待と違ったことと失敗を書く。うまくいったことだけを書かない
- 仕組みの説明は docs/ に書き、記録からは docs/ を指す
- 人が言ったことは、人の言葉に近い形で書く
