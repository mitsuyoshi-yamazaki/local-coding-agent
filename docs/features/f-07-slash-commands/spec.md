# F-07 slash commands: 実装前の仕様

[作る機能](../../features.md) の F-07 の、実装の前に決めた仕様である。

## 何をするか

端末で `/` で始まる行を打つと、ハーネスがコマンドとして処理する。コマンドには2種類ある。

- **組み込みのコマンド**: ハーネスの中に書いた処理（`/help`・`/clear`・`/context`・`/mode`・`/exit`）。モデルは呼ばず、会話の履歴にも入らない
- **自作のコマンド**: 利用者がファイルに書いた手順を、`/<名前>` で呼ぶ。ハーネスがファイルを読み、引数を入れた中身を、利用者の依頼としてモデルに送る

この機能で確かめたいのは、コマンドはハーネスが処理し、モデルに渡るのは中身の文だけであること、である。組み込みのコマンドはモデルに何も渡らない。自作のコマンドも、モデルが受け取るのは展開した文と、ハーネスが入れる「どのコマンドから来たか」の知らせだけで、ファイルを読むのも引数を入れるのもハーネスである。

## 入力

- 起動と依頼の打ち方は F-06 と同じ
- **コマンドとみなす行**: 行の頭（前に空白が無い）が `/` で、`/` から空白までの語が `/<名前>` の形のもの。名前は英小文字・数字・`-`・`_` からなり、英小文字か数字で始まる。語の後ろの文（前後の空白を除く）が引数である
- それ以外の行は、F-06 までと同じく依頼として送る。`/tmp/a.txt を読んで` は、語に `/` を含むので依頼である
- 名前の形に合うが、組み込みにも自作にも無い名前（`/tmp を見て` の `tmp` など）は、誤りを出し、モデルに送らない。依頼として送りたいときは、行の頭に空白を置く
- **自作のコマンドのファイル**: 作業ディレクトリの `.local-coding-agent/commands/<名前>.md`（UTF-8）。呼ぶたびに読む（書き換えは次に呼んだときから効く）。下の一段だけで、サブディレクトリは読まない

自作のコマンドのファイルの形:

```markdown
---
description: テストを走らせ、失敗していれば直す
---

テストを走らせよ。失敗していれば、出力を読んで直し、もう一度走らせよ。
対象: $ARGUMENTS
```

- 頭の `---` の行から次の `---` の行までを、前付け（frontmatter）として読む。前付けの中で読むのは `description: <文>` の行だけで、ほかの行は使わない（Claude Code のファイルにある `allowed-tools` などの欄を書いても、誤りにしない）。値を `"…"` か `'…'` で囲んでいれば、囲みを外す
- 閉じる `---` が無ければ、前付けは無く、全体が本文である
- `description` が無ければ、本文の最初の空でない行を説明にする（Claude Code と同じ）

## 出力

### 組み込みのコマンド

| コマンド | 引数 | すること | 画面 |
|---|---|---|---|
| `/help` | 無し | コマンドの一覧を出す | 組み込みの名前と説明・自作の名前と説明（下） |
| `/clear` | 無し | 会話の履歴を空にする。最後の要求の入力トークン数も忘れる | `（会話を消した。次の依頼から新しい会話になる）` |
| `/context` | 無し | 今の履歴の発言の数と、最後の要求の入力トークン数を出す | `[文脈] 発言 12（依頼 3・モデル 5・道具の結果 4）・最後の要求の入力 3210 トークン` |
| `/mode` | 無し、または `<モード>` | 許可のモードを見る。モードを渡せば変える | `許可のモード: ask` ／ `許可のモード: ask → accept-edits` |
| `/exit` | 無し | 終える（Ctrl-D と同じ） | 無し |

- 引数を取らないコマンドに引数を付けたら、何もせず `/<名前> は引数を取らない` を出す
- `/mode` の知らないモードは、何もせず誤りを出す（使えるモードを添える）。変えたモードは、その会話の間だけ効き、設定ファイルには書かない。規則は変わらない
- `/context` の数え方:
  - 依頼: 利用者の発言のうち、道具の結果を持たないもの（自作のコマンドで送ったものも含む）
  - モデル: モデルの発言
  - 道具の結果: 利用者の発言のうち、道具の結果を持つもの
  - 最後の要求の入力: 最後に終わりまで届いた応答の `prompt_eval_count`（Ollama が数えた入力のトークン数）。まだ無い・`/clear` の後は `まだ無い`
- `/clear` の後も、走行の記録の回の番号（`turn`）は続けて数える

`/help` の画面の例:

```text
組み込みのコマンド:
  /help     コマンドの一覧を出す
  /clear    会話の履歴を消し、新しい会話にする
  /context  今の履歴の発言の数と、最後の要求の入力トークン数を出す
  /mode     許可のモードを見る。/mode <モード> で変える（ask・accept-edits・allow-all）
  /exit     終える
自作のコマンド（.local-coding-agent/commands/）:
  /explain  ファイルの役目を短く説明する
  /fix      テストを走らせ、失敗していれば直す
```

- 自作のコマンドが無ければ `  （無し）` を出す
- 組み込みと同じ名前の自作のコマンドは、組み込みが勝つ。一覧では `（組み込みと同じ名前なので呼べない）` を付ける
- 名前の形に合わないファイル（`Fix.md` など）は、一覧に `（名前に使えない字があるので呼べない）` を付けて出す
- 読めないファイル（UTF-8 でないなど）は、一覧に `（読めない: <理由>）` を付けて出す

### 自作のコマンド

- **引数の入れ方**: 本文の `$ARGUMENTS` を、全て引数に置き換える（引数が無ければ空の文字列）。本文に `$ARGUMENTS` が無く、引数があれば、本文の末尾に空の行を挟んで `ARGUMENTS: <引数>` を足す（Claude Code と同じ）
- 置き換えた文の前後の空白を除き、空なら誤りを出し、モデルに送らない
- 送る前に、`[コマンド] /<名前> → .local-coding-agent/commands/<名前>.md（<行数> 行を依頼として送る）` の1行を出す
- モデルに送る利用者の発言: 本文は置き換えた文。メタデータに、打った行（`/<名前> <引数>`）を持つ。送る直前に、送った時刻と並べて `<metadata>` に入れる

```text
<metadata>
送った時刻: 2026-10-28 15:30 (+09:00)
コマンド: /fix test_temperature.py
</metadata>
テストを走らせよ。失敗していれば、出力を読んで直し、もう一度走らせよ。
対象: test_temperature.py
```

- その後の回の流れ（応答・道具・許可・Ctrl-C）は、打った依頼と同じである
- ファイルが無い名前は、上の「知らない名前」と同じ誤り。ファイルが読めなければ `誤り: /<名前> を読めない: <理由>` を出し、モデルに送らない

### 誤りの表示

- 知らない名前: `誤り: 知らないコマンド: /<名前>（/help で一覧。依頼として送るなら、行の頭に空白を置く）`
- どの誤りでも、履歴は変わらず、回の番号も進まない

### 走行の記録

コマンドの行ごとに1件（`type` が `command`）を書く。

| 欄 | 中身 |
|---|---|
| `line` | 打った行 |
| `name` | 名前 |
| `kind` | `builtin`（組み込み）・`custom`（自作）・`unknown`（知らない名前） |
| `turn` | 自作のコマンドで依頼を送ったときは、その回の番号。ほかは `null` |
| `source` | 自作のコマンドのファイル（作業ディレクトリからのパス）。ほかは `null` |
| `text` | 自作のコマンドで送った本文（置き換えた後）。送らなければ `null` |
| `output` | 画面に出した文（`/help` の一覧・`/mode` の変わり・誤りの文など） |

## 振る舞い

### 行の流れ

1. 空の行は、今と同じく捨てる
2. コマンドとみなす行なら、名前で探す。組み込み → 自作の順に探し、先に見つかったものを使う
3. 組み込みなら、その処理を行う。モデルは呼ばない
4. 自作なら、ファイルを読み、引数を入れ、依頼として回を始める
5. どちらでもなければ、誤りを出す
6. コマンドでない行は、今と同じく依頼として回を始める

### REPL の持つもの

REPL は、会話の間、次を持つ。組み込みのコマンドは、これを受けて、新しいものを返す（書き換えない）。

- 許可の設定を含む session（`/mode` が、モードを替えた session を作る）
- 会話の履歴（`/clear` が空にする）
- 回の番号
- 最後の要求の入力トークン数（ループが回ごとに返す）
- 終えるか（`/exit`）

### ループが返すもの

ループ（`run_turn`）は、新しい履歴に加え、その回で最後に終わりまで届いた応答の入力トークン数を返す。回の中で応答が1つも終わりまで届かなければ、無し（REPL は前の値を保つ）。

### system prompt

既定の指示の「ハーネスが入れる情報」の `<metadata>` の項に、次を足す: 「コマンド: 」の行があれば、利用者がそのコマンドを呼び、ハーネスが、コマンドのファイルの中身（引数を入れたもの）を、その発言の本文として送った。

組み込みのコマンドは、指示に書かない（モデルには何も渡らないので）。

## Claude Code との対応

- Claude Code も、`/` で始まる行をコマンドとして扱う。コマンドは行の頭でだけ認め、名前の後ろの文が引数になる（出典）
- 組み込みの `/clear`（会話の履歴を消し、新しい会話にする）・`/help`（使えるコマンドを出す）・`/exit`（終える）がある。`/context` は、文脈の使い方を、system prompt・道具・発言などの区分ごとのトークン数で出す。ここでは、発言の数と、Ollama が数えた入力のトークン数の合計だけを出す（手元ではトークンを数える道具を持たない）（出典）
- 会話の途中でモードを変えるのは、端末の Shift+Tab である。`/permissions` は規則を見る・直す画面で、モードは変えない。ここでは `/mode` で変える（出典）
- 自作のコマンドは `.claude/commands/<名前>.md` に書く。今の Claude Code では、自作のコマンドは skills にまとめられ、`.claude/skills/<名前>/SKILL.md` と同じに働く（モデルが自分で呼ぶこともできる。このリポジトリでは F-08）。前付けの `description` が無ければ本文の最初の空でない行を使う・`$ARGUMENTS` が無くて引数があれば末尾に `ARGUMENTS: <引数>` を足す、はここと同じ（出典）
- Claude Code は、ほかに `$0`・`$1`（`$ARGUMENTS[N]`）の位置の引数・`` !`コマンド` ``（送る前にコマンドを走らせ、出力に置き換える）・`allowed-tools`（その回で問わずに使える道具）・`model` を持つ（出典）

## テスト

`tests/` に、標準ライブラリの `unittest` で書く。実物のモデルにも、通信にも繋がない。

- 行の見分け: `/help`・引数つき・前後の空白・頭に空白・`/tmp/a.txt …`・`/`・大文字・`-` と `_`・数字で始まる名前
- 自作のコマンド: 前付けの有る無し・閉じない前付け・`description` の囲み・説明の代わりの最初の行・`$ARGUMENTS` の置き換え（複数か所・引数が空）・末尾の `ARGUMENTS:`・空の本文・UTF-8 でないファイル・無い名前・一覧（並び・名前の形に合わないファイル・読めないファイル・ディレクトリが無い）
- 組み込み: `/help` の一覧（組み込みと同じ名前の自作）・`/clear` で次の要求が空の履歴から始まる・`/context` の数え方と `まだ無い`・`/mode` で次の道具の判定が変わる・知らないモード・`/exit` で終わる・引数を取らないコマンドに引数
- REPL（偽物のモデルで）: 組み込みはモデルを呼ばない・自作は展開した文と `<metadata>` のコマンドの行を送る・知らない名前は送らず回の番号も進まない・走行の記録の `command` の件
- ループ: 返す入力トークン数（終わりまで届いた最後の応答・届かなかった回）
- 会話の形: メタデータのコマンドの行が `<metadata>` に入る
- 既定の指示がコマンドの行に触れている

## 試し方

人が、main 側で、手元の Ollama とモデルで試す。材料は `tasks/f-07-slash-commands/` に置き、F-05・F-06 と同じく、写しを作業ディレクトリにして起動する。材料は、テストが失敗する小さなプロジェクトと、自作のコマンドのファイル（`$ARGUMENTS` を使うもの・使わないもの・前付けの無いもの）である。

| 課題 | 打つもの | 見ること |
|---|---|---|
| 一覧 | `/help` | 組み込みと自作が出る。モデルを呼ばない（数値の行が出ない） |
| 自作のコマンドで直させる | `/fix test_temperature.py` | 送った発言（走行の記録の `request`）が展開した文と `<metadata>` のコマンドの行を持つ。テストが通ったか（判定のコマンドの終了コード） |
| 引数の入れ方 | `$ARGUMENTS` の無いコマンドに引数を付ける | 末尾の `ARGUMENTS:` をモデルが読むか |
| 会話を消す | 何かを話す → `/context` → `/clear` → `/context` → 前の話を尋ねる | 発言の数が 0 になる。モデルが前の話を知らない |
| モードを変える | `/mode ask` → 直させる | 書く前とコマンドの前に問う |

数値（応答までの時間・トークン数・課題を通せたか）は、走行の記録から取る。
