# F-03 道具の呼び出しとループ: 実装前の仕様

[作る機能](../../features.md) の F-03 の、実装の前に決めた仕様である。

## 何をするか

モデルに、ファイルを読む道具と、ディレクトリの中身を見る道具を渡す。1回の依頼の中で、モデルが道具を呼ぶ間、「モデルを呼ぶ → 道具を実行する → 結果を履歴に足す」を繰り返し、道具を呼ばない応答が来たら終える。変更を伴う道具は、実行の前に人に確かめる。

この機能で確かめたいのは、チャット（F-01・F-02）とエージェントの違いが、道具の呼び出しとループにあることである（[コーディングエージェントの仕組み](../../how-coding-agents-work.md#エージェントのループ)）。

## 入力

- 起動と依頼の打ち方は F-02 と同じ
- 変更を伴う道具を呼ぶときは、実行の前に `実行してよいか [y/N]: ` と問い、1行を受ける

## 出力

- モデルを1回呼ぶたびに、応答の本文を流して表示し、数値の1行を出す（F-01 と同じ形）
- 道具を実行するたびに、呼び出しを1行（`[道具] read_file {"path": "README.md"}`）、結果を1行（`→ 120 行`、誤りなら `→ 誤り: …`）で表示する
- 走行の記録:
  - 要求と応答の件に、その回の中で何回目にモデルを呼んだか（`step`）を足す
  - 応答の件に、道具の呼び出しを足す
  - 道具を実行するたびに、1件を書く（呼び出しの id・道具の名前・入力・確かめたか・結果・誤りか・時間）

## 振る舞い

### ループ

1. 利用者の依頼を履歴に足し、道具の定義と一緒にモデルを呼ぶ
2. 応答に道具の呼び出しがあれば、応答（本文と呼び出し）を履歴に足し、呼び出しを順に実行し、結果をまとめて履歴に足して、1 のモデルの呼び出しへ戻る
3. 応答に道具の呼び出しが無ければ、応答を履歴に足して、その回を終える

- 1回の応答で、道具を複数呼んでもよい。順に1つずつ実行する
- ループの回数に上限は設けない。止めるのは人の Ctrl-C である
- **Ctrl-C と誤り**: モデルの応答の途中・道具の実行の途中・確かめる問いの途中で Ctrl-C を押したとき、またはモデルの誤りが起きたときは、その回の全体（依頼と、それまでの道具の呼び出しと結果）を履歴に足さない。F-01 と同じ扱いである。F-03 の道具は読むだけなので、捨てても失われるものは無い。書く道具ができる F-04 で見直す

Claude Code は、Esc で止めると実行中の道具を取り消して人の指示を待つ。会話は、それまでの歩みを残したまま続く（出典）。

### 会話の形と、Ollama の形への変換

Claude の Messages API に揃え、塊を2つ足す。

| 塊 | 欄 | 入る発言 |
|---|---|---|
| `tool_use` | `id`・`name`・`input` | モデルの発言（本文の塊の後） |
| `tool_result` | `tool_use_id`・`content`（文）・`is_error` | 利用者の発言。1回の応答の呼び出しの結果を、まとめて1つの発言にする |

道具の定義は、Messages API と同じく `name`・`description`・`input_schema`（JSON Schema）で持つ。

送る直前に、Ollama の `/api/chat` の形へ変える。

| このリポジトリの形 | Ollama の形 |
|---|---|
| 道具の定義 | 要求の `tools` の1つ（`type` が `function`、`function` に `name`・`description`・`parameters`） |
| モデルの発言の `tool_use` | その発言の `tool_calls` の1つ（`id`・`function` に `index`・`name`・`arguments`） |
| 利用者の発言の `tool_result` | `role` が `tool` の発言1つ（`tool_name`・`tool_call_id`・`content`）。`is_error` の欄は Ollama に無いので、誤りの結果は `content` の先頭に「誤り: 」を足す |

- 応答では、`message.tool_calls` を、流れてくる塊の全てから集める
- Ollama が呼び出しに `id` を付けなければ、ハーネスが付ける
- 推論の文（`message.thinking`）は、F-01 と同じく捨てる。Ollama の文書は、道具を使うときに推論の文も履歴に戻すことを例に示すが、F-09 で扱う

### 道具

道具は1つを1ファイルに置く。名前と説明は、モデルに渡す定義に入る。

**`read_file`**: ファイルを読む。

| 入力 | 型 | 意味 |
|---|---|---|
| `path` | 文字列。必須 | 読むファイル。作業ディレクトリからの相対パスか、絶対パス |
| `offset` | 1 以上の整数 | 何行目から読むか。既定は 1 |
| `limit` | 1 以上の整数 | 何行読むか。既定は 2000 |

- 結果は、`cat -n` と同じ形（右に寄せた行番号・タブ・行）で返す
- 2000 字を超える行は、2000 字で切り、切ったことを書き添える
- 読み残した行があれば、全体の行数と、続きは `offset` で読めることを、結果の末尾に書く
- 空のファイルは、空であることを返す

**`list_directory`**: ディレクトリの中身を1段だけ見る。

| 入力 | 型 | 意味 |
|---|---|---|
| `path` | 文字列 | 見るディレクトリ。作業ディレクトリからの相対パスか、絶対パス。既定は作業ディレクトリ |

- 結果は、中の名前を1行に1つ、名前の順に並べる。ディレクトリには、名前の末尾に `/` を付ける

**両方に共通**:

- 作業ディレクトリの外も読める（要件の「素の状態では基本的に全て許可」。規則は F-06）
- 次のときは、`is_error` の結果としてモデルに返し、ループを続ける: ファイルやディレクトリが無い・種類が違う（ディレクトリを `read_file` で読むなど）・UTF-8 として読めない・入力が定義の形に合わない（必須の欄が無い・型が違う）
- 知らない名前の道具が呼ばれたときも、`is_error` の結果（使える道具の名前を添える）を返す

Claude Code の Read の道具は、行番号を付けて返し、`offset` と `limit` で大きなファイルを分けて読む。作業ディレクトリの外のパスを読むときは、人に確かめる（出典）。

### 実行の前に確かめる

- 道具は「変更を伴うか」の印を持つ。印のある道具だけ、実行の前に人に問う。`y` か `yes`（大文字も可）なら実行する。それ以外の答えと入力の終わり（Ctrl-D）は、拒んだとする
- 拒んだら、道具を実行せず、「利用者が実行を拒んだ」を `is_error` の結果として返し、ループを続ける。モデルは、拒まれたことを読んで、やり方を変えうる
- F-03 の2つの道具は読むだけなので、印を持たない。問いが実際に出るのは、書く道具ができる F-04 からである。F-03 では、偽物の道具を使うテストで確かめる

Claude Code では、ファイルの変更とコマンドの実行の前に問う（Manual のモード）。理由を添えずに拒むと、その回を止める。理由を添えて拒むと、理由をモデルに渡して続ける。Agent SDK でも、拒んだ理由はモデルに渡り、モデルはやり方を変えうる（出典）。ここでは理由を打つ欄を作らず、拒んでも続ける。

### system prompt

既定の指示を直す。

- 「できること」: ファイルを読む道具（`read_file`）とディレクトリの中身を見る道具（`list_directory`）を持つ。ファイルを書く・コマンドを走らせる道具は持たない
- 「道具の使い方」の節を足す: ファイルの中身やディレクトリの様子が要るときは、推測せずに道具で確かめる・パスは作業ディレクトリからの相対パスか絶対パス・結果を読んでから続けて呼んでよく、一度に複数を呼んでもよい・答えに要ることが揃ったら道具を呼ばずに答える・長いファイルの続きは `offset` と `limit` で読む
- 「ハーネスが入れる情報」に、道具の結果を足す

Ollama の文書は、モデルに、ループの中にいて道具を何度も呼べることを伝えるとよい、と書く（出典）。

`tasks/f-02-system-prompt/` の指示のファイルは、F-02 で試すための材料なので直さない（「道具を持たない」と書いたまま）。

## 作らないこと

| 作らないこと | 作る機能 |
|---|---|
| ファイルを書く・編集する道具 | F-04 |
| コマンドを走らせる道具 | F-05 |
| 許可の規則とモード・作業ディレクトリの外を確かめること | F-06 |
| 推論の文の表示と、履歴に戻すこと | F-09 |
| ループの回数の上限 | F-10 |
| 同じ呼び出しの繰り返しの検出 | F-17 |

ほかに、ファイルの名前の型での検索（Claude Code の Glob）・中身の検索（Grep）・画像や PDF の読み込み・道具の並列の実行・拒むときに理由を打つこと・止めた回の歩みを残すことは作らない。

## テスト

`tests/` に、標準ライブラリの `unittest` で書く。実物のモデルにも、通信にも繋がない。

- 変換: 道具の定義・`tool_use` から `tool_calls`・`tool_result` から `tool` の発言（誤りの印）・応答の `tool_calls` の読み取り（`id` の有無・読めない形）
- 道具: `read_file`（行番号・`offset` と `limit`・読み残しの知らせ・長い行・空のファイル・無い・ディレクトリ・UTF-8 でない・入力の誤り）・`list_directory`（並び・`/`・無い・ファイルを渡したとき）
- 確かめる: `y`・`yes`・それ以外・入力の終わり
- ループ（台本どおりに道具を呼ぶ偽物のモデルで）: 道具の結果を足してもう一度呼ぶ・道具を呼ばない応答で終わる・1回の応答の複数の呼び出し・知らない道具・変更を伴う偽物の道具を許す／拒む・途中の Ctrl-C と誤りで、その回の全体を履歴に足さない・走行の記録と表示

## 試し方

人が、main 側で、手元の Ollama とモデルで試す。材料は `tasks/f-03-tool-loop/` に置く。

1. 2つのファイルを辿らないと答えられない問いを出す（例: 説明のファイルが設定のファイルの場所を示し、その設定のファイルに答えがある）。モデルが `list_directory` と `read_file` を何回呼び、何回目のモデルの呼び出しで答えたかを、走行の記録で見る
2. 2000 行を超えるファイルの後ろの方に答えがある問いを出す。モデルが `offset` で続きを読むかを見る。文脈の長さが足りないと、読んだ結果が入りきらない
3. 無いファイルを読ませる。誤りの結果を読んで、どう答えるかを見る
4. 応答の途中や道具の実行の後で Ctrl-C を押し、次の回の要求にその回が入っていないことを見る

数値（モデルを呼んだ回数・入力のトークン数の伸び方・時間）は、走行の記録から取る。F-03 はコードを直せないので、失敗するテストを直す課題には掛けない。
