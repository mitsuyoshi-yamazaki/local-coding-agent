# F-05 コマンドの実行と、結果を読んで直すループ: 実装前の仕様

[作る機能](../../features.md) の F-05 の、実装の前に決めた仕様である。

## 何をするか

モデルに、シェルのコマンドを走らせる道具（`run_command`）を渡す。モデルは、コードを直した後にこの道具でテストを走らせ、終了コードと出力を道具の結果として読む。失敗していれば直して、もう一度走らせる。テストを走らせると決めるのはモデルで、ハーネスは指示で促すだけである（編集の後に、ハーネスが自動では走らせない）。

この機能で確かめたいのは、「確かめる」とは、コマンドの出力を道具の結果として読むことだ、ということである。モデルが、直した後にテストを走らせるか・失敗の出力から直す所を見つけるか・通ったことを確かめてから終えるかを、走行の記録で見る。

## 入力

- 起動と依頼の打ち方は F-03 と同じ
- `run_command` を実行する前に、走らせるコマンドを表示して `実行してよいか [y/N]: ` と問い、1行を受ける（F-03 の確かめる問い）

## 出力

- 道具の呼び出しの1行（`[道具] run_command {…}`）の後、問いの前に、下見として `$ <コマンド>` を表示する
- 道具の結果の1行: `run_command` は `→ 終了コード: 1・<行数> 行`（時間切れなら `→ 時間切れ: 120 秒で止めた・<行数> 行`）。ほかの道具は F-03 と同じ `→ <行数> 行`、誤りなら `→ 誤り: …`
- 走行の記録: F-04 と同じ欄。`preview` に `$ <コマンド>`、`result` にモデルに返した結果の文が入る

## 振る舞い

### 道具

**`run_command`**: シェルのコマンドを走らせ、終了コードと出力を返す。

| 入力 | 型 | 意味 |
|---|---|---|
| `command` | 文字列。必須 | 走らせるコマンド |
| `timeout` | 整数。1 以上 600 以下 | 終わるのを待つ秒数。過ぎたら止める。既定は 120 |

- 走らせ方: `/bin/sh -c <command>`。作業ディレクトリは、毎回、エージェントを起動したディレクトリである。コマンドの中の `cd` は、次のコマンドに残らない。別のディレクトリで走らせるときは、`cd sub && make` のように1つのコマンドに書く
- 環境変数: エージェントの環境変数を、そのまま子のプロセスに渡す。コマンドの中で設定した環境変数は、次のコマンドに残らない
- 標準入力: 空（`/dev/null`）。入力を待つコマンドは、入力の終わりを受けて進む
- 出力: 標準出力と標準エラーを1つにまとめる（端末で見るときと同じ順になる）。UTF-8 として読み、読めない字は置き換える
- 子のプロセスは、新しいプロセスのグループで走らせる。時間切れのときと、コマンドが終わったときに、グループに残ったプロセス（シェルが後ろで走らせたものなど）をまとめて止める
- Ctrl-C: 端末の Ctrl-C は、エージェントだけが受ける（子のプロセスは別のグループにいるため）。エージェントは子のプロセスのグループを止め、その回を F-04 の止めた回の扱いにする（その呼び出しと、まだ結果の無い呼び出しに `利用者が止めた` の誤りの結果を入れ、済んだ歩みまでを履歴に残す）

結果の文の例:

```text
終了コード: 1
F.
======================================================================
FAIL: test_parse (test_duration.DurationTest.test_parse)
…
FAILED (failures=1)
```

- 1行目は `終了コード: <N>`。時間切れなら `時間切れ: <秒> 秒で止めた`。2行目からは出力で、出力が無ければ `（出力なし）`
- 終了コードが 0 でないときも、時間切れのときも、誤りの結果（`is_error`）にしない。テストの失敗は、モデルが求めた情報であり、道具の失敗ではないためである。誤りの結果にするのは、コマンドを走らせられなかったときだけである
- 出力が 10,000 字を超えたら、先頭の 5,000 字と末尾の 5,000 字を残し、間に `（中略: <省いた字数> 字。全体は <全体の字数> 字）` の1行を挟む。テストの失敗の詳しいことは前に、まとめは後ろに出るので、両方を残す。手元のモデルの文脈が狭いので、Claude Code より小さくする
- 誤り（`is_error`）: `command` が空・コマンドを走らせられない（作業ディレクトリが無い、など）・`command` に NUL の字がある

Claude Code の Bash は、時間切れの既定が 2 分、モデルが選べる上限が 10 分で、出力は 30,000 字まで結果に入れる。コマンドの中の `cd` は次のコマンドに残る（毎回、元のディレクトリに戻す設定 `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` がある）。環境変数は次のコマンドに残らない。コマンドを後ろで走らせることもできる（出典）。

### テストを走らせるのはモデル

- ハーネスは、編集の後にテストを自動では走らせない。テストを走らせるのは、モデルが `run_command` を呼んだときだけである。system prompt で、直した後にテストを走らせて確かめるよう促す
- Claude Code も、モデルが Bash の道具でテストを走らせる。Aider は、`--test-cmd` と `--auto-test` を渡すと、モデルがコードを編集するたびにハーネスがテストのコマンドを走らせ、終了コードが 0 でなければ、モデルに直させる（出典）

### 入力の照らし

道具の入力を定義と照らす処理（`tools/input_check.py`）に、数の上限（JSON Schema の `maximum`）を足す。`timeout` が 600 を超えれば、実行せずに `入力が定義に合わない: timeout は 600 以下でなければならない（受けた値: 900）` を返す。

### 結果の1行

道具は、結果の文から、画面に出す結果の1行を作る関数を持てる。持たない道具は、F-03 と同じく行数を出す。`run_command` は、結果の文の1行目（終了コードか時間切れ）と行数を出す。テストが通ったかを、人が画面で追えるようにするためである。

### system prompt

既定の指示を直す。

- 「できること」: 「コマンドを走らせる道具は持たない。テストを走らせて確かめることはできない」を除き、コマンドを走らせる道具（`run_command`）を持ち、実行の前に利用者が確かめる、を足す
- 「道具の使い方」: コードを直したら、`run_command` でテストを走らせて確かめる。失敗したら、出力を読んで直し、もう一度走らせる。通ったことを確かめてから答える・テストの走らせ方は README などで確かめる・`run_command` は毎回作業ディレクトリで走り、`cd` は次のコマンドに残らない・標準入力は空なので、入力を待つコマンドと終わらないコマンド（サーバなど）は走らせない
- 「ハーネスが入れる情報」: `run_command` の結果の1行目は、終了コード（0 なら成功）か時間切れである

## 作らないこと

| 作らないこと | 作る機能 |
|---|---|
| 許可の規則とモード（読むだけのコマンドを問わずに通す、など）・走らせてよいコマンドの制限 | F-06 |
| 同じ失敗の繰り返しの検出・「終わった」と言ったときにテストの結果を見せて確かめさせること | F-17 |
| 決まった時点（道具の実行の前後・ターンの終わり）に設定したコマンドを走らせること | F-18 |

ほかに、ハーネスが編集の後にテストを自動で走らせること（Aider の `--auto-test`）・後ろで走らせ続けるコマンド・`cd` と環境変数を次のコマンドに残すこと・出力を流しながら表示すること・端末を使う対話のコマンド・シェルを選ぶこと・Windows・出力の全体を別のファイルに残すことは作らない。

## テスト

`tests/` に、標準ライブラリの `unittest` で書く。実物のモデルにも、通信にも繋がない。コマンドは本物の `/bin/sh` で、一時ディレクトリの中で走らせる。

- プロセス: 終了コードと出力・標準エラーをまとめる・標準入力が空・作業ディレクトリ・時間切れ（途中までの出力を返す・シェルが後ろで走らせたプロセスも止まる）・Ctrl-C（グループを止めて、投げ直す）
- `run_command`: 結果の文（終了コード・出力なし・時間切れ）・0 でない終了コードを誤りにしない・切り詰め・誤り（空・作業ディレクトリが無い・NUL の字）・下見・結果の1行
- 入力の照らし: 上限
- ループ（偽物のモデルと、本物の `run_command`）: 下見を表示してから問う・許すと走る・拒むと走らない・結果の1行
- 既定の指示が `run_command` を書いている・既定の組

## 試し方

人が、main 側で、手元の Ollama とモデルで試す。材料は `tasks/f-05-run-command/` に置き、F-04 と同じく、写しを作業ディレクトリにして起動する（試すたびに写し直す）。

| 課題 | 依頼の例 | 判定 | 見ること |
|---|---|---|---|
| 出力を読んで直す | `テストを走らせて、通らないものを直せ` | 写しのテストが通る | テストの走らせ方を README で確かめるか。失敗の出力から直す所を見つけるか。直した後に走らせ直すか |
| 終わらないテスト | 同じ | 写しのテストが通る | 時間切れの結果を読んで、終わらない所を見つけるか |

- 判定のコマンドは、写しのテストを、時間を限って走らせ、終了コードで返す。直っていない終わらないテストでも、判定が止まらないようにする。コマンドは `tasks/f-05-run-command/README.md` に置く
- ほかに、問いで拒んだときと、コマンドの途中で Ctrl-C を押したときに、モデルがどうするかを見る

数値（コマンドを走らせた回数と終了コード・時間切れの回数・編集の回数・課題を通せたか・モデルを呼んだ回数・時間）は、走行の記録から取る。
