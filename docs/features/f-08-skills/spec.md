# F-08 skills: 実装前の仕様

[作る機能](../../features.md) の F-08 の、実装の前に決めた仕様である。

## 何をするか

スキル（skill）は、作業ごとの手順書である。ハーネスは、起動のときにスキルを探し、**名前と説明だけ**をモデルへの指示に入れる。モデルは、依頼がスキルの説明に合うと判断したら、道具 `load_skill` を呼ぶ。ハーネスは、そのスキルの**本文**を道具の結果として返す。本文が指すファイル（手順の細部・観点の一覧など）は、モデルが要るときに `read_file` で読む。

読み込みは次の3段になる。

| 段 | モデルに渡るもの | いつ |
|---|---|---|
| 一覧 | 全てのスキルの名前と説明 | 毎回の要求（system prompt に入る） |
| 本文 | 選んだスキルの `SKILL.md` の本文 | モデルが `load_skill` を呼んだとき |
| 付いているファイル | スキルのディレクトリの中のファイル | 本文を読んだモデルが、要ると判断して `read_file` で読んだとき |

利用者も、`/<スキルの名前>` と打ってスキルを呼べる（F-07 の自作のコマンドと同じ打ち方）。このときは、ハーネスが本文を利用者の発言として送る。

この機能で確かめたいのは、必要になったときだけ読み込むことで、文脈を使わずに多くの手順を持てること、である。毎回の要求に入るのは一覧だけで、本文は選んだときに1度だけ会話に入る。

## 入力

### スキルの置き場とファイル

- 作業ディレクトリの `.local-coding-agent/skills/<名前>/SKILL.md`（UTF-8）。置き場の下の一段のディレクトリだけを見て、さらに下は探さない
- スキルの名前は、ディレクトリの名前である。名前の形は F-07 の自作のコマンドと同じ（英小文字・数字・`-`・`_` からなり、英小文字か数字で始まる）
- `SKILL.md` の形は、F-07 の自作のコマンドのファイルと同じである。前付けの中で読むのは `description` だけで、無ければ本文の最初の空でない行を説明にする。本文の `$ARGUMENTS` が引数に置き換わる

```markdown
---
description: 長さの単位の変換を足す手順（引数: 足す変換。例: inch → cm）
---

長さの単位の変換を足すときは、次の順に行う。

1. convert.py の RATES に行を足す
2. ...

足す変換: $ARGUMENTS
```

- スキルのディレクトリには、`SKILL.md` のほかのファイル（`checklist.md`・`scripts/` など）を置ける。ハーネスはその中身を読まず、一覧だけをモデルに渡す

### いつ読むか

- **一覧**: 起動のときに1度だけ探す。会話の途中で足した・消したスキルは、起動し直すまで一覧に入らない（system prompt を起動のときに1度だけ組み立てるため。F-02）
- **本文**: 読み込むたびに `SKILL.md` を読む。書き換えは、次に読み込んだときから効く（F-07 の自作のコマンドと同じ）

### 使えないスキル

次のものは一覧に入れず、`/help` に理由を出す。起動は止めない。

| 理由 | `/help` の行 |
|---|---|
| ディレクトリの名前が、名前の形に合わない | `Foo/  （名前に使えない字があるので使えない）` |
| `SKILL.md` が無い | `notes/  （SKILL.md が無いので使えない）` |
| `SKILL.md` を読めない（UTF-8 でない・権限が無い） | `broken/  （SKILL.md を読めない: <理由>）` |
| 本文が空（前付けだけ） | `empty/  （本文が空なので使えない）` |
| 置き場の中を見られない | `.local-coding-agent/skills/  （読めない: <理由>）` |

置き場の下のディレクトリでないもの（`README.md` など）は、見ない。

## 出力

### system prompt の「# スキル」の節

使えるスキルが1つ以上あれば、環境の節の後に、ハーネスが次の節を足す。`--system-prompt-file` で指示を差し替えても残る（環境の節と同じ）。使えるスキルが無ければ、節を足さない。

```text
# スキル

スキルは、作業ごとの手順書である。下に、作業ディレクトリに置かれたスキルの名前と説明を並べる。依頼がスキルの説明に合えば、作業を始める前に load_skill の道具でそのスキルを読み込み、本文の手順に従う。合うスキルが無ければ、読み込まない。

- add-conversion: 長さの単位の変換を足す手順（引数: 足す変換。例: inch → cm）
- release: 版を上げて、リリースの準備をする（引数: 新しい版。例: 1.1.0）
- review: コードを読み、誤りや分かりにくい所を挙げる。ファイルは書き換えない（引数: 対象のファイル）
```

並びは名前の順。説明の長さに上限は置かない。

### 道具 load_skill

使えるスキルが1つ以上あるときだけ、モデルに渡す道具に足す。

| 欄 | 型 | 中身 |
|---|---|---|
| `name` | 文字列（必須） | スキルの名前。定義の `enum` に、使えるスキルの名前を並べる |
| `arguments` | 文字列（省ける） | 本文の `$ARGUMENTS` に入れる引数。省けば空の文字列 |

- 結果は、下の「スキルの中身」である
- 種類は「読む」（何も変えない）。許可は、F-06 の読む道具と同じくモードで通る。規則は、名前だけの規則（`load_skill`）が合う。型を持つ規則（`load_skill(review)`）は合わない（照らす文字列を持たない道具なので）
- `enum` に無い名前は、入力の照らし（F-03）で誤りにする: `入力が定義に合わない: name は次のどれか: add-conversion, release, review（受けた値: "x"）`。入力の照らしに `enum` を足す
- 読めないときは、誤りの結果 `スキル <名前> を使えない: <理由>` を返す（理由は `SKILL.md を読めない: <理由>`・`本文が空`・`引数を入れた中身が空`）
- 画面の表示は、ほかの道具と同じ（`[道具] load_skill {"name": "review", "arguments": "convert.py"}` と、結果の行数）

### スキルの中身

`load_skill` の結果と、`/<名前>` で送る発言の本文は、同じ文である。

```text
<本文。$ARGUMENTS を入れたもの>

スキルのディレクトリ: .local-coding-agent/skills/review/（本文の中の相対パスは、ここからのもの）
付いているファイル（要るときに read_file で読む）:
- .local-coding-agent/skills/review/checklist.md
```

- 本文: 前付けを除き、F-07 の自作のコマンドと同じく引数を入れる（`$ARGUMENTS` を全て置き換える。無くて引数があれば、末尾に `ARGUMENTS: <引数>` を足す）
- 付いているファイル: スキルのディレクトリの中の、`SKILL.md` のほかのファイル（下のディレクトリも含む）を、作業ディレクトリからのパスで名前の順に並べる。中身は読まない。50 を超えたら、50 までを並べ、`（ほかに <数> 個。list_directory で見る）` を足す
- 付いているファイルが無ければ、後ろの3行（空の行・ディレクトリ・一覧）を付けず、本文だけにする

### 利用者が /<名前> で呼ぶ

- 行の見分けは F-07 のとおり。名前は、組み込みのコマンド → 自作のコマンド → スキルの順に探し、先に見つかったものを使う
- スキルなら、上の「スキルの中身」を作り、利用者の依頼として回を始める。送る前に、`[スキル] /<名前> → .local-coding-agent/skills/<名前>/SKILL.md（<行数> 行を依頼として送る）` を出す
- 送る発言のメタデータに、打った行を持つ。送る直前に、送った時刻と並べて `<metadata>` に入れる

```text
<metadata>
送った時刻: 2026-10-28 15:30 (+09:00)
スキル: /review convert.py
</metadata>
対象のファイルを読み、checklist.md の観点ごとに、当てはまる所を挙げよ。...
```

- 読めないときは `誤り: /<名前> のスキルを使えない: <理由>` を出し、送らない。履歴は変わらず、回の番号も進まない
- 一覧に入っていない名前（起動の後に足したスキル・使えないスキル）は、知らない名前の誤り（F-07）になる

### /help

自作のコマンドの後に、スキルを並べる。

```text
スキル（.local-coding-agent/skills/。/<名前> で呼ぶか、モデルが読み込む）:
  /add-conversion  長さの単位の変換を足す手順（引数: 足す変換。例: inch → cm）
  /release         版を上げて、リリースの準備をする（引数: 新しい版。例: 1.1.0）
  /review          コードを読み、誤りや分かりにくい所を挙げる。…
```

- 名前の列は、組み込み・自作・スキルの全体で揃える
- スキルが無ければ `  （無し）`
- 組み込みと同じ名前のスキルには `（組み込みと同じ名前なので /<名前> では呼べない。モデルは読み込める）`、自作のコマンドと同じ名前のスキルには `（自作のコマンドと同じ名前なので /<名前> では呼べない。モデルは読み込める）` を付ける
- 使えないスキルは、上の「使えないスキル」の行を出す
- スキルの一覧は、起動のときに探したものを使う（自作のコマンドと同じ名前かは、`/help` を打ったときに見る）

### 起動の行

許可の行の後、`コマンド: /help で一覧` の前に1行を出す。

```text
スキル: 3（add-conversion・release・review）
スキル: 3（add-conversion・release・review）・使えない 1（/help で理由）
スキル: 無し
```

### 走行の記録

- 起動のときに1件（`type` が `skills`）を書く

| 欄 | 中身 |
|---|---|
| `skills` | 使えるスキルの並び。1つが `name`・`source`（`SKILL.md` の、作業ディレクトリからのパス）・`description` |
| `unusable` | 使えないスキルの並び。1つが `entry`（ディレクトリの名前か置き場）・`problem`（理由） |

- `load_skill` の呼び出しは、ほかの道具と同じ `tool` の件に入る（入力と結果の全文）
- `/<名前>` でスキルを呼んだ行は、F-07 の `command` の件に入る。`kind` は `skill`、`source` は `SKILL.md` のパス、`text` は送った本文

### system prompt の既定の指示

「ハーネスが入れる情報」に、次を足す。

- この指示の後の「# スキル」の節（あれば）: 作業ディレクトリに置かれたスキルの名前と説明。読み込み方は、その節にある
- `<metadata>` の「スキル: 」の行: 利用者が `/<名前>` でそのスキルを呼び、ハーネスが、スキルの中身（引数を入れたもの）を、その発言の本文として送った。そのスキルを `load_skill` で読み込み直さない

## 振る舞い

### 起動

1. 作業ディレクトリの置き場を探し、使えるスキルと使えないスキルに分ける
2. 使えるスキルがあれば、`load_skill` を道具に足し、system prompt に「# スキル」の節を足す
3. 許可の設定ファイルの規則は、`load_skill` を知っている道具として読む（使えるスキルが無くても、`load_skill` の規則は誤りにしない）
4. 起動の行と、走行の記録の `skills` の件を書く

### モデルが読み込む

1. モデルが `load_skill` を呼ぶ
2. 入力の照らし（`enum`）と許可の判定は、ほかの道具と同じ
3. ハーネスが `SKILL.md` を読み、スキルの中身を作って、道具の結果として返す
4. 中身は道具の結果として履歴に残り、後の回でも送られる。`/clear` で消える。同じスキルをもう一度呼べば、もう一度読み、もう一度履歴に足す

## Claude Code との対応

- Claude Code のスキルは、`.claude/skills/<名前>/SKILL.md`（プロジェクト）と `~/.claude/skills/<名前>/SKILL.md`（個人）などに置く。前付けの欄は全て省けて、`description` だけが推奨される。`name` を省けば、ディレクトリの名前が名前になる（出典）
- Claude Code は、通常のセッションでは、スキルの説明を文脈に入れ、本文は呼んだときにだけ読み込む。説明と `when_to_use` は、一覧の中では合わせて 1,536 字で切る。一覧の全体には、文脈窓の 1% の字数の予算があり、超えると、使われることの少ないスキルから説明を落とす（出典）。ここでは、予算も切り詰めも作らない
- Claude Code では、Claude は Skill の道具でスキルを呼ぶ。呼んだスキルの本文は1つの発言として会話に入り、後の回でも残る。後の回でファイルを読み直さない（出典）。ここでは、モデルが呼べば道具の結果として、利用者が呼べば利用者の発言として入る
- Claude Code では、利用者も `/<名前>` でスキルを呼べる。利用者も Claude も引数を渡せ、`$ARGUMENTS` に入る。置き換わる所が無ければ、末尾に `ARGUMENTS: <引数>` が足される（出典）。ここも同じ
- Claude Code は、`disable-model-invocation: true`（説明を文脈に入れず、Claude は呼べない。利用者は呼べる）と `user-invocable: false`（`/` で呼べない。説明は文脈に入る）を持つ（出典）。ここでは作らない。利用者だけが呼ぶ手順は、F-07 の自作のコマンドに書く
- 付いているファイルは、`SKILL.md` から指し、Claude が要るときに読む（出典）。ここでは、スキルの中身に置き場と一覧を添える
- Agent Skills の規格（agentskills.io）は、読み込みを3段（一覧は1つあたり約 100 トークンで起動のときに全て・本文は 5,000 トークン未満を勧め、選んだときに・付いているファイルは要るときに）に分ける。名前は英小文字・数字・ハイフンの 64 字までで、ディレクトリの名前と合わせる。一覧を system prompt に置くか、読み込む道具の説明に置くかは、どちらでもよいとしている（出典）

| 作らないこと | 作る機能 |

| 要約のときに、スキルの中身を残すこと | F-12 |
| スキルを別の会話で走らせること（Claude Code の `context: fork`） | F-19 |
| スキルが持つ hooks | F-18 |

ほかに、家のディレクトリの置き場・`.claude/skills/` と `.agents/skills/` を読むこと・入れ子の置き場・前付けの `description` のほかの欄（`name`・`when_to_use`・`disable-model-invocation`・`user-invocable`・`allowed-tools`・`model`・`effort`・`paths`・`argument-hint` など）・位置の引数（`$0`・`$1`）・`${CLAUDE_SKILL_DIR}`・`` !`コマンド` `` の前処理・一覧の字数の予算と説明の切り詰め・会話の途中で一覧を入れ直すこと・同じスキルを2度読み込ませないこと・型を持つ `load_skill` の規則・作業ディレクトリのスキルを信頼するかの確かめは、作らない。

## テスト

`tests/` に、標準ライブラリの `unittest` で書く。実物のモデルにも、通信にも繋がない。

- 探す: 名前の順・ディレクトリでないものを見ない・使えない理由の5つ・置き場が無い・説明の代わりの最初の行
- 「# スキル」の節: 並び・スキルが無ければ空・system prompt で環境の節の後に入る・`--system-prompt-file` でも残る
- スキルの中身: 前付けを除く・`$ARGUMENTS`・末尾の `ARGUMENTS:`・付いているファイル（下のディレクトリ・`SKILL.md` を除く・50 を超えたとき・無いとき）・読むたびに読む・読めない・本文が空
- 道具: 定義の `enum`・結果・読めないときの誤り・種類が「読む」・入力の照らしの `enum`
- REPL（偽物のモデルで）: `/<名前>` でスキルの中身と `<metadata>` のスキルの行を送る・自作のコマンドが勝つ・読めないときは送らない・走行の記録の `command` の件・`/help` の一覧（揃え・同じ名前・使えない）・モデルが `load_skill` を呼んだ回で結果が履歴に入る
- 起動: 道具と節が、スキルがあるときだけ入る・起動の行・走行の記録の `skills` の件・スキルが無くても `load_skill` の規則を読める
- 既定の指示が「# スキル」の節と「スキル: 」の行に触れている

## 試し方

人が、main 側で、手元の Ollama とモデルで試す。材料は `tasks/f-08-skills/` に置く。小さなプロジェクト（長さの単位の変換と、そのテストと、変更の記録）と、スキルの置き場に写す3つのスキルである。

| スキル | 中身 |
|---|---|
| `add-conversion` | 変換を足す手順。表に足す・テストに足す・変更の記録に足す・テストを走らせる。変更の記録に足すことは、頼まれなければモデルがしない |
| `review` | 観点の一覧（付いているファイル `checklist.md`）に沿ってコードを読む。観点は本文に無く、`checklist.md` を読まないと分からない |
| `release` | 版を上げる手順。上の2つの依頼には合わない |

| 課題 | 打つもの | 見ること |
|---|---|---|
| 合う依頼で読み込む | `インチとセンチメートルの変換を足して` | `load_skill` で `add-conversion` を読み込むか。手順どおり変更の記録にも足したか（判定のコマンドの終了コード） |
| 付いているファイルを読む | `convert.py をレビューして` | `review` を読み込んだ後に、`checklist.md` を `read_file` で読むか。答えが観点に沿うか（人が判定） |
| 合わない依頼で読まない | `convert.py の役目を1行で説明して` | `load_skill` を呼ばないか |
| `/<名前>` で呼ぶ | `/review convert.py` | `[スキル]` の行。送った発言が `<metadata>` のスキルの行を持つ。モデルが `load_skill` で読み込み直さないか |
| 一覧の大きさ | スキルを写した写しと、写さない写しで、同じ依頼を送る | 1つ目の要求の入力トークン数の差（一覧の大きさ）と、`load_skill` の後の要求で増えた数（本文の大きさ） |

数値（応答までの時間・トークン数・課題を通せたか）は、走行の記録から取る。
