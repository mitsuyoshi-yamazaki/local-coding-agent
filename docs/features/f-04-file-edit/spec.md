# F-04 ファイルの書き込みと編集: 実装前の仕様

[作る機能](../../features.md) の F-04 の、実装の前に決めた仕様である。

## 何をするか

モデルに、ファイルを丸ごと書く道具（`write_file`）と、ファイルの中の文字列を置き換える道具（`edit_file`）を渡す。どちらも変更を伴う道具なので、実行の前に差分を見せて人に確かめる。`edit_file` は、置き換え元がファイルの中身とそのままでは合わないとき、行末の空白と字下げのずれを除いて、段階的に緩めて探す。

この機能で確かめたいのは、編集の失敗が、内容の誤り（読んでいない・覚え違えた中身を置き換え元にした）と、写し間違い（読んだ中身を写すときに空白や字下げを違えた）の、どちらで起きるかである。そのために、置き換え元がどの段で見つかったか、見つからなければファイルのどこに最も近かったかを、結果に書く。結果は、モデルに渡り、走行の記録にも残る。

## 入力

- 起動と依頼の打ち方は F-03 と同じ
- `write_file`・`edit_file` を実行する前に、差分を表示して `実行してよいか [y/N]: ` と問い、1行を受ける（F-03 の確かめる問い）

## 出力

- 道具の呼び出しの1行（`[道具] edit_file {…}`）の後、問いの前に、書く前と後の中身の差分を表示する
- 道具の結果の1行は F-03 と同じ形（`→ <行数> 行`、誤りなら `→ 誤り: …`）
- 走行の記録: 道具の件に、人に見せた差分（`preview`）を足す。見せなかった道具では `null`

## 振る舞い

### 道具

**`write_file`**: ファイルを丸ごと書く。

| 入力 | 型 | 意味 |
|---|---|---|
| `path` | 文字列。必須 | 書くファイル。作業ディレクトリからの相対パスか、絶対パス |
| `content` | 文字列。必須 | 書く中身の全体 |

- ファイルが無ければ作る。親のディレクトリが無ければ、それも作る
- ファイルがあれば、中身を `content` で置き換える
- 結果: `新しいファイルを書いた: <パス>（<行数> 行）` か `上書きした: <パス>（<行数> 行）`

**`edit_file`**: ファイルの中の `old_string` を `new_string` に置き換える。

| 入力 | 型 | 意味 |
|---|---|---|
| `path` | 文字列。必須 | 直すファイル |
| `old_string` | 文字列。必須 | 置き換える元 |
| `new_string` | 文字列。必須 | 置き換えた後 |
| `replace_all` | 真偽値 | 真なら、合う所を全て置き換える。既定は偽 |

- 置き換え元は、下の「段階的に緩めて探す」で探す
- 結果: 置き換えた行と、見つけた段を書く。1か所なら、置き換えた所の前後3行を、`read_file` と同じ形（行番号・タブ・行）で添える。例:

```text
置き換えた: inventory.py の 5 行目（段: そのまま）
     2	    """数の合計。"""
     3	    total = 0
     4	    for _, count in rows:
     5	        total += count
     6	    return total
```

**両方に共通**:

- 文字コードは UTF-8 で読み書きする
- 改行: 既存のファイルの改行が `\r\n` なら、`\n` に揃えて扱い、書くときに `\r\n` に戻す
- 次のときは、`is_error` の結果としてモデルに返し、ループを続ける

| 道具 | 誤り |
|---|---|
| 両方 | パスがディレクトリである・既存のファイルが UTF-8 として読めない・書いても中身が変わらない・書けない（権限など）・パスとして使えない |
| `edit_file` | ファイルが無い（新しいファイルは `write_file` で作る、と添える）・`old_string` が空・`old_string` と `new_string` が同じ・置き換え元が見つからない・2か所以上に合うのに `replace_all` が偽 |

Claude Code の Edit は、`old_string` が今の中身にそのまま1か所だけ合うときに置き換える。2か所以上に合えば、モデルは前後を足して1か所に絞るか、`replace_all` を真にする。Write は、新しいファイルを作るか、既存のファイルを丸ごと書き換える。既存のファイルを書き換える前に、そのファイルを会話の中で読んでいることを求める（モデルによる）（出典）。

### 段階的に緩めて探す

`edit_file` は、置き換え元を、次の3段で順に探す。

| 段 | 比べ方 | 置き換え方 |
|---|---|---|
| 1. そのまま | `old_string` を、ファイルの中の文字列としてそのまま探す。行の一部でもよい | 合った所を `new_string` にする |
| 2. 行末の空白を除く | 行の単位で比べる。`old_string` の行の並びと、ファイルの連続した行の並びを、行末の空白（スペース・タブ）を除いて比べる | 合った行の全体を、`new_string` の行にする |
| 3. 字下げのずれを除く | 2 に加えて、比べる行の並びの全体に共通する字下げを、`old_string` とファイルのそれぞれから除いて比べる。`old_string` の字下げが、ファイルより一様に深い・浅いときに合う | 合った行の全体を `new_string` の行にする。`new_string` の行の字下げを、`old_string` とファイルのずれの分だけ直す |

- 段 1 から順に探し、合う所が見つかった最初の段で置き換える。結果に、その段の名前を書く
- その段で2か所以上に合い、`replace_all` が偽なら、置き換えずに誤りを返す。後の段には進まない。誤りには、合った行を書き、前後の行を足して1か所に絞るか、`replace_all` を真にするよう添える
- 段 2・3 では、`old_string` の末尾の改行1つを無視する。`new_string` も同じ
- 3段のどれでも見つからなければ、誤りを返す。誤りに、次を添える
  - **最も近い所**: ファイルの中の、`old_string` と同じ行数の連続した行のうち、似ている度合い（Python の `difflib.SequenceMatcher` の `ratio`。0 から 1）が最も高い所の行番号と度合い。度合いが 0.6 以上なら、その行を `read_file` と同じ形で添える。0.6 未満なら度合いだけを書き、ファイルを読み直すよう添える
  - **行番号の写し込み**: `old_string` の空でない行が全て、`read_file` の結果の行番号の形（空白・数字・タブ）で始まっていれば、行番号とタブまで写していることを添える

走行の記録の結果の文から、編集を次のように分けられる。

| 結果 | 読み方 |
|---|---|
| 段 1 で見つかった | 正しく写した |
| 段 2・3 で見つかった | 空白・字下げを写し間違え、ハーネスが補った |
| 見つからず、最も近い所の度合いが高い | ハーネスが補えない写し間違い（タブをスペースにした・語を1つ違えた、など） |
| 見つからず、度合いが低い | 内容の誤り（読んでいない・別のファイルや別の所の中身を置き換え元にした） |

手本にしたもの:

- Codex（OpenAI のコーディングエージェント）の `apply_patch` は、置き換える行を、そのまま → 行末の空白を除く → 行頭と行末の空白を除く → 記号の字（引用符・ダッシュ・特殊な空白）を揃える、の順で探す（出典）
- Aider は、そのまま → 字下げのずれを除く（ずれを置き換え後の行にも当てる）の順で探す。見つからなければ、似ている度合いが 0.6 以上の最も近い行を「この行のつもりだったか」と添えてモデルに返す（出典）
- Claude Code の Edit は、そのままの一致だけで置き換える（出典）

ここでは、行頭の空白を行ごとに除く段（Codex の3段目）を作らない。合ったときに `new_string` の字下げをどう直すかが決まらず、Python のように字下げに意味のある言語で、置き換えた行の字下げが崩れうるからである。

### 実行の前に確かめる

- 道具は、実行の前に人に見せる文を作る関数（下見）を持てる。`write_file` と `edit_file` の下見は、書く前と後の中身の差分（unified diff。前後3行。Python の `difflib.unified_diff`）を返す。新しいファイルは、書く前を空として差分にする
- 道具の呼び出しを処理する順は、道具があるか → 入力が定義に合うか → 下見 → 人に問う → 実行、になる。下見が誤り（置き換え元が見つからない、など）なら、人に問わずに誤りの結果を返す
- 下見の差分は、呼び出しの1行の後、問いの前に表示する
- 実行のときは、道具がファイルを読み直して変更を組み立て直す。問いを待つ間にファイルが変わると、見せた差分と違う変更が書かれうる（変わったかを確かめることは作らない）

Claude Code の Manual のモードでは、編集を1つずつ、その場で承認する（出典）。

### 止めた回と誤りの回

F-03 では、その回の全体を履歴に足さなかった。F-04 からはファイルを書くので、書いた後に止めると、モデルは書いたことを知らないまま次の回に進み、ファイルとモデルの知っている中身が食い違う。そこで、済んだ歩みまでを履歴に残す。

| 止まった所 | 履歴に残すもの |
|---|---|
| 1回目のモデルの応答の途中（Ctrl-C・モデルの誤り） | 何も残さない（F-03 と同じ） |
| 2回目以降のモデルの応答の途中（Ctrl-C・モデルの誤り） | 依頼と、済んだ歩み（それまでの応答と道具の結果）。途中の応答は捨てる |
| 道具の実行の途中・問いの途中（Ctrl-C） | 依頼と、済んだ歩みと、その道具を呼んだ応答。その応答の呼び出しのうち、まだ結果の無いものには、`利用者が止めた` の誤りの結果を入れる |

- 残すときは、最後の発言（道具の結果の発言）の末尾に、止まったことの知らせを本文の塊で足す。Ctrl-C なら `（利用者がこの回を途中で止めた）`、モデルの誤りなら `（誤りで、この回が途中で止まった）`
- 表示: `（止めた）` か `誤り: …` の1行の後に、`（この回は履歴に足さない）` か `（済んだ歩みまでを履歴に残す）` の1行を出す
- 走行の記録: `利用者が止めた` の結果を入れた呼び出しも、道具の件を書く

Claude Code は、Esc で止めると実行中の道具を取り消して人の指示を待つ。会話は、それまでの歩みを残したまま続く（[F-03 の仕様](../f-03-tool-loop/spec.md#ループ)の出典）。

### system prompt

既定の指示を直す。

- 「できること」: ファイルを書く道具（`write_file`）と、一部を置き換える道具（`edit_file`）を持つ。どちらも実行の前に利用者が確かめ、拒まれたら、やり方を変えるか利用者に尋ねる。コマンドを走らせる道具は持たないので、テストを走らせて確かめることはできない
- 「道具の使い方」: 既存のファイルを直す前に `read_file` で読む・一部を直すときは `edit_file`、新しいファイルと全体の書き直しは `write_file`・`old_string` は `read_file` の結果から行番号とタブを除き、字下げと空白を含めてそのまま写す・1か所だけに合うよう前後の行を含める
- 「ハーネスが入れる情報」: 回が途中で止まったことの知らせ

| 作らないこと | 作る機能 |

| コマンドを走らせる道具（テストを走らせて確かめる） | F-05 |
| 許可の規則とモード・編集を確かめずに通すモード・パスの制限 | F-06 |

## テスト

`tests/` に、標準ライブラリの `unittest` で書く。実物のモデルにも、通信にも繋がない。ファイルは一時ディレクトリに作る。

- 探し方: 段 1（行の一部・複数の行）・段 2（行末の空白）・段 3（字下げが深い・浅い。`new_string` の字下げを直す）・段の順（前の段で見つかれば後の段で探さない）・2か所以上に合う（`replace_all` の偽と真）・見つからない（最も近い所の行番号と度合い・0.6 未満・行番号の写し込み）・末尾の改行
- `write_file`: 新しいファイル（親のディレクトリを作る）・上書き・中身が変わらない・ディレクトリ・`\r\n` のファイル・差分
- `edit_file`: 結果の文と前後3行・誤り（無い・空・同じ・UTF-8 でない・ディレクトリ）・`\r\n` のファイル・差分
- ループ（偽物のモデルで）: 差分を表示してから問う・下見の誤りでは問わない・許すと書く・拒むと書かない・走行の記録の `preview`
- 止めた回: 1回目の応答の途中は残さない・2回目の応答の途中は済んだ歩みを残す・問いの途中は結果の無い呼び出しに `利用者が止めた` を入れる・知らせの本文・モデルの誤り・表示

## 試し方

人が、main 側で、手元の Ollama とモデルで試す。材料は `tasks/f-04-file-edit/` に置く。材料を `.tmp/` などへ写し、写しを作業ディレクトリにして起動する（モデルがリポジトリの中の答えを読まないため。試すたびに写し直す）。

| 課題 | 依頼の例 | 使う道具 | 判定 |
|---|---|---|---|
| バグを直す | `test_inventory.py のテストが通るように、inventory.py を直せ` | `edit_file` | `test_inventory.py` が通る |
| 新しいファイルを作る | `test_report.py のテストが通るように、report.py を作れ` | `write_file` | `test_report.py` が通る |
| 表を直す | `stock.txt の、ねじの数を 40 にせよ` | `edit_file`（タブ区切りで、行末に空白のある行がある） | `test_stock.py` が通る |

- 判定は、写しに対して `unittest` を走らせ、終了コードで見る。コマンドは `tasks/f-04-file-edit/README.md` に置く
- ほかに、問いで拒んだときにモデルがどうするか、書いた後の回の途中で Ctrl-C を押し、次の回でモデルが書いたことを知っているか（走行の記録の、次の回の要求）を見る

数値（編集の回数・見つかった段・見つからなかった回数と最も近い所の度合い・拒んだ回数・課題を通せたか・モデルを呼んだ回数・時間）は、走行の記録から取る。
