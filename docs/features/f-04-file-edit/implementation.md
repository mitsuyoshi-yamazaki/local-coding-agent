# F-04 ファイルの書き込みと編集: 実装した仕様と仕組み

[実装前の仕様](spec.md) に対して、実際に実装した仕様と、その仕組みである。

## 使い方

起動は F-03 と同じである。モデルが `write_file` か `edit_file` を呼ぶと、呼び出しの1行の後に差分が出て、実行してよいかを問われる（数値は例）。

```text
> test_inventory.py のテストが通るように、inventory.py を直せ

[入力 1630 トークン・出力 31 トークン・最初の文字まで 2.40 秒・全体 2.95 秒]
[道具] read_file {"path": "inventory.py"}
→ 21 行
…
[道具] edit_file {"path": "inventory.py", "old_string": "        total = count", "new_string": "        total += count"}
--- inventory.py
+++ inventory.py
@@ -12,7 +12,7 @@
     """数の合計。"""
     total = 0
     for _, count in rows:
-        total = count
+        total += count
     return total
 
 
実行してよいか [y/N]: y
→ 8 行
```

- 差分は、書く前と後の中身の unified diff（前後3行）である。新しいファイルは、`--- /dev/null` からの差分になる
- `y` か `yes` で書く。それ以外の答えと Ctrl-D では書かず、`利用者が実行を拒んだ` をモデルに返す
- 置き換え元が見つからないなど、書けないことが下見で分かったときは、差分も問いも出さず、`→ 誤り: …` を出してモデルに返す
- 結果の1行は F-03 と同じく、モデルに返した結果の文の行数である。`edit_file` の結果は、置き換えた所の前後の行を含むので、行数が多めに出る
- **Ctrl-C**: 1回目の応答の途中なら、その回を履歴に足さない。それより後なら、済んだ歩みまでを履歴に残す。表示は次のとおり

```text
[道具] edit_file {"path": "stock.txt", "old_string": "ねじ\t12", "new_string": "ねじ\t40"}
--- stock.txt
…
実行してよいか [y/N]: ^C
（止めた）
（済んだ歩みまでを履歴に残す）
>
```

## 仕組み

### 道具の形と、実行の前の下見

F-03 の道具（`tools/tool.py` の `Tool`）に、下見の関数（`preview`）を足した。下見は、実行する関数と同じ入力と作業ディレクトリを受け、何も変えずに、人に見せる文を返す。書けないと分かれば `ToolError` を投げる。

`loop/tool_call.py` の `execute` は、呼び出しを次の順で処理する。3 と 4 が F-04 で足した所である。

| 順 | 見ること | 止まったときにモデルに返す結果 |
|---|---|---|
| 1 | その名前の道具があるか | `知らない道具: …` |
| 2 | 入力が定義に合うか | `入力が定義に合わない: …` |
| 3 | 変更を伴う道具なら、下見を作れるか。作れたら表示する | 下見が投げた誤りの文（人には問わない） |
| 4 | 変更を伴う道具なら、人が許すか | `利用者が実行を拒んだ` |
| 5 | 道具を実行する | 道具が投げた誤りの文 |

下見と実行は、それぞれファイルを読み、変更を組み立てる。問いを待つ間にファイルが変わると、実行は変わった後の中身から組み立て直すので、見せた差分と違う変更が書かれうる。

Claude Code の Manual のモードでも、編集は1つずつ、その場で承認する（出典）。

### ファイルを書く2つの道具

2つの道具は、入力から「書く前と後の中身」を組み立てる関数（`plan`）だけを持つ。差分を作る・書く・結果を返すのは共通の部品（`tools/file_change.py`）で、`file_tool` が、`plan` から下見（差分）と実行（書き込み）を作る。

| 部品 | 中身 |
|---|---|
| `FileChange` | 書くファイル・モデルが渡したパス・書く前の中身（新しいファイルなら無し）・書いた後の中身・ファイルの改行・書いた後にモデルに返す文 |
| `read_current` | 今の中身を UTF-8 で読み、改行を `\n` に揃える。改行が全て `\r\n` のファイルは、改行を `\r\n` として覚える。`\r\n` と `\n` が混ざっていれば、誤り `改行に \r\n と \n が混ざっている: <パス>（書き換えない）`。ファイルが無ければ「無い」を返す |
| `checked` | 書く前と後の中身が同じなら、誤り `書いても中身が変わらない: <パス>` |
| `diff_text` | 書く前と後の中身の差分（Python の `difflib.unified_diff`。前後3行）。末尾に改行が無い中身は、git と同じく最後の行の後に `\ No newline at end of file` の行を置く。末尾の改行だけを変えたときも、差分が空にならない |
| `write` | 親のディレクトリを作り、改行をファイルの改行に戻して、UTF-8 で書く |

**`write_file`**（`tools/write_file.py`）

| 入力 | 型 | 意味 |
|---|---|---|
| `path` | 文字列。必須 | 書くファイル |
| `content` | 文字列。必須 | 書く中身の全体 |

- 結果: `新しいファイルを書いた: <パス>（<行数> 行）` か `上書きした: <パス>（<行数> 行）`
- 既存のファイルの改行が `\r\n` なら、`content` の改行も `\r\n` にして書く
- 誤り: ディレクトリである・既存のファイルが UTF-8 として読めない（`（書き換えない）` を添える）・既存のファイルの改行が混ざっている・中身が変わらない・書けない（権限など）・パスとして使えない

**`edit_file`**（`tools/edit_file.py`）

| 入力 | 型 | 意味 |
|---|---|---|
| `path` | 文字列。必須 | 直すファイル |
| `old_string` | 文字列。必須 | 置き換える元 |
| `new_string` | 文字列。必須 | 置き換えた後 |
| `replace_all` | 真偽値 | 真なら、合う所を全て置き換える。既定は偽 |

結果は、置き換えた行と、見つけた段である。1か所なら、置き換えた後の中身の、その行と前後3行を `read_file` と同じ形で添える。2か所以上なら、行番号だけを並べる。

```text
置き換えた: stock.txt の 2〜3 行目（段: 行末の空白を除く）
     1	# 名前	数
     2	ねじ	40
     3	ばね	5
     4	ナット	30 
     5	座金	8
```

```text
置き換えた: a.txt の 2 か所（1・3 行目。段: そのまま）
```

誤り: ファイルが無い（`新しいファイルは write_file で作る` を添える）・`old_string` が空・`old_string` と `new_string` が同じ・置き換え元が見つからない・2か所以上に合うのに `replace_all` が偽（合った行の番号と、前後の行を足すか `replace_all` を真にするよう添える）・`write_file` と同じ読み書きの誤り。

行の分け方（`\n` で分け、末尾の改行の後は行にしない）と、行番号を付けた形（6桁で右に寄せた行番号・タブ・行。2000 字を超える行は切る）は、`tools/lines.py` にあり、`read_file` と `edit_file` が共に使う。

### 段階的に緩めて探す

`tools/text_match.py` の `find` が、置き換え元を3段で探す。合う所が見つかった最初の段で止め、その段で合った全ての所を返す。

| 段 | 比べ方 | 置き換え方 |
|---|---|---|
| そのまま | `old_string` を、文字列としてそのまま探す。行の一部でもよい。重ならない所を全て探す | 合った所を `new_string` にする |
| 行末の空白を除く | 行の単位で比べる。`old_string` の行と、ファイルの連続した行を、行末のスペースとタブを除いて比べる | 合った行の全体を、`new_string` の行にする |
| 字下げのずれを除く | 行末の空白を除いた上で、比べる行の並びに共通する字下げ（空でない行の全てに共通する、行頭の空白）を、`old_string` とファイルのそれぞれから除いて比べる | 合った行の全体を `new_string` の行にする。`new_string` の行のうち、`old_string` の共通の字下げで始まる行は、その字下げをファイルの共通の字下げに替える |

- 行の単位の2つの段では、`old_string` と `new_string` の末尾の改行を1つ無視する。`new_string` が空なら、合った行を除く
- 行の全体を置き換えるので、合った行の行末の空白は残らない（`new_string` に無ければ）
- 合った所の次の行から続けて探すので、合う所は重ならない
- 字下げのずれは、行の並びの全体で一様でなければ合わない（1行目は 4 字、2行目は 8 字ずれている、は合わない）。字下げのタブとスペースの違いも合わない
- 字下げを直さない行: 空の行と、`old_string` の共通の字下げで始まらない行は、そのまま置く

例: `inventory.py` の 14・15 行目は、8 字と 12 字ではなく、4 字と 8 字で字下げされている。次の `old_string` は、字下げが 4 字浅い。

```json
{"old_string": "for _, count in rows:\n    total = count",
 "new_string": "for _, count in rows:\n    total += count"}
```

そのままの段では見つからない（`for` の前に 4 字の空白がファイルにあるが、2行目は 4 字の空白の直後に `total` が来ない）。行末の空白を除く段でも見つからない。字下げのずれを除く段で、ファイルの共通の字下げ（4 字）と `old_string` の共通の字下げ（無し）を除くと合い、`new_string` の2行に 4 字を足して置く。

**見つからないとき**: `edit_file` は、誤りの文に次を添える。

- 最も近い所（`nearest`）: ファイルの中の、`old_string` と同じ行数の連続した行を全て、`difflib.SequenceMatcher` の `ratio`（2つの文字列の似ている度合い。0 から 1）で比べ、最も高い所を選ぶ。ファイルの行数が `old_string` より少なければ、ファイルの全体と比べる
  - 度合いが 0.6 以上: `最も近いのは <行> 行目（似ている度合い <度合い>）:` と、その行（行番号付き）
  - 0.6 未満: `最も近い所でも、似ている度合いは <度合い>（<行> 行目）。ファイルを read_file で読み直す`
  - 空のファイル: `ファイルは空である`
- 行番号の写し込み（`has_line_numbers`）: `old_string` の空でない行が全て、空白・数字・タブで始まっていれば、`old_string の行が、read_file の結果の行番号とタブで始まっている。行番号とタブは除いて写す`

例（`stock.txt` の、タブをスペース4つにして写した `old_string`。実測）:

```text
置き換え元が見つからない: stock.txt（そのまま・行末の空白を除く・字下げのずれを除く、の3段で探した）
最も近いのは 4 行目（似ている度合い 0.62）:
     4	ナット	30 
```

この結果から、編集を次のように分けられる。

| 結果 | 読み方 |
|---|---|
| 段が「そのまま」 | 正しく写した |
| 段が「行末の空白を除く」か「字下げのずれを除く」 | 空白・字下げを写し間違え、ハーネスが補った |
| 見つからず、最も近い所の度合いが高い | ハーネスが補えない写し間違い（タブをスペースにした・語を1つ違えた、など） |
| 見つからず、度合いが低い | 内容の誤り（読んでいない・別の所の中身を置き換え元にした） |

手本の Codex は、そのまま → 行末の空白 → 行頭と行末の空白 → 記号の字、の4段で探す。Aider は、そのまま → 字下げのずれ（置き換え後にも当てる）で探し、見つからなければ度合い 0.6 以上の最も近い行を添える。Claude Code の Edit は、そのままの一致だけで置き換える（出典）。

### 止めた回と誤りの回

`loop/turn.py` の `run_turn` は、止まった回でも、済んだ歩みまでを履歴に残す。歩みは、呼び出しを含む応答と、その呼び出しの結果の組である。

| 止まった所 | 履歴に残すもの | 表示 |
|---|---|---|
| 1回目の応答の途中（Ctrl-C・モデルの誤り） | 何も残さない | `（止めた）` か `誤り: …` の後に `（この回は履歴に足さない）` |
| 2回目以降の応答の途中（Ctrl-C・モデルの誤り） | 依頼と、それまでの歩み。途中の応答は捨てる | `（止めた）` か `誤り: …` の後に `（済んだ歩みまでを履歴に残す）` |
| 道具の実行・下見・問いの途中（Ctrl-C） | 依頼と、それまでの歩みと、その道具を呼んだ応答。その応答の呼び出しのうち、まだ結果の無いもの（止めたときのものを含む）には `利用者が止めた` の誤りの結果を入れる | `（止めた）` の後に `（済んだ歩みまでを履歴に残す）` |

- 残すときは、最後の発言（道具の結果の発言）の末尾に、本文の塊を1つ足す。Ctrl-C なら `（利用者がこの回を途中で止めた）`、モデルの誤りなら `（誤りで、この回が途中で止まった）`。Ollama の形では、`tool` の発言の後の `user` の発言になる（[F-03 の変換](../f-03-tool-loop/implementation.md#ollama-の形への変換)）
- 呼び出しの全てが結果を持つので、残した履歴は Messages API の形のまま（`tool_use` の後に、同じ id の `tool_result` がある）である
- 次の回の依頼は、この知らせの発言の後に続く
- 表示や記録の途中など、上の外で押された Ctrl-C も、同じ扱いにする
- `loop/tool_call.py` の `run_tool_calls` は、結果の並びと、途中で止めたかを返す（`ToolResults`）

Claude Code も、Esc で止めると実行中の道具を取り消し、会話はそれまでの歩みを残したまま続く（[F-03 の仕様](../f-03-tool-loop/spec.md#ループ)の出典）。

### system prompt

`context/system_prompt.py` の既定の指示を、次のように直した。

| 節 | 足したこと |
|---|---|
| できること | `write_file` と `edit_file` を持つ。どちらも実行の前に利用者が差分を見て確かめ、拒まれたらやり方を変えるか利用者に尋ねる。コマンドを走らせる道具は持たず、テストを走らせて確かめることはできない |
| 道具の使い方 | 既存のファイルを直す前に `read_file` で読む。一部を直すときは `edit_file`、新しいファイルと全体の書き直しは `write_file`。`old_string` は `read_file` の結果から行番号とタブを除き、字下げと空白を含めてそのまま写し、1か所だけに合うよう前後の行を含める |
| ハーネスが入れる情報 | 道具の結果の後の `（利用者がこの回を途中で止めた）` などの知らせ。止まる前に済んだ道具の結果は、そのまま効いている |

### 走行の記録

F-03 の道具の件（[欄](../f-03-tool-loop/implementation.md#走行の記録)）に、欄を1つ足した。

| 欄 | 中身 |
|---|---|
| `preview` | 実行の前に人に見せた下見（差分）。見せなかったら `null`（読むだけの道具・下見が誤りだったとき・止めた呼び出し） |

- `edit_file` の見つけた段と、見つからなかったときの最も近い所は、`result`（モデルに返した文）に入る
- Ctrl-C で止めた回では、まだ結果の無かった呼び出しにも道具の件を書く。`result` は `利用者が止めた`、`is_error` は `true`、`confirmed`・`seconds`・`preview` は `null` である

## 試すための材料

`tasks/f-04-file-edit/project/` に、通らないテストを持つ小さなプロジェクトを置く。写し方と判定のコマンドは `tasks/f-04-file-edit/README.md` にある。写しを作業ディレクトリにして起動し（モデルがリポジトリの中の答えを読まないため）、試すたびに写し直す。

| ファイル | 中身 |
|---|---|
| `inventory.py` | タブ区切りの表を読む `load` と、数の合計の `total_count`。`total_count` は、足すべき所で代入している（`total = count`） |
| `stock.txt` | タブ区切りの在庫の表（見出しの行と4行）。2行目と4行目の行末に空白がある |
| `test_inventory.py` | `total_count` のテスト |
| `test_report.py` | `report.py` の `low_stock(rows, threshold)` のテスト。数が `threshold` より少ない品目の名前を、表の順に返す |
| `test_stock.py` | `load` で読んだ `stock.txt` が、ねじ 40・ばね 5・ナット 30・座金 8 であるかのテスト |

| 依頼の例 | 使う道具 | 判定 | 見ること |
|---|---|---|---|
| `test_inventory.py のテストが通るように、inventory.py を直せ` | `edit_file` | `test_inventory.py` が通る | 直す前に両方を読むか。見つけた段 |
| `test_report.py のテストが通るように、report.py を作れ` | `write_file` | `test_report.py` が通る | テストを読んでから書くか |
| `stock.txt の、ねじの数を 40 にせよ` | `edit_file` | `test_stock.py` が通る | タブと行末の空白を写せるか。見つからなかったとき、最も近い所を読んで呼び直すか |

ほかに、問いで拒んだときにモデルがどうするか、書いた後の回の途中で Ctrl-C を押し、次の回の要求に済んだ歩みと知らせが入るか（走行の記録の `request` の件の `body.messages`）を見る。

道具を写しに直に掛けて、正しく直せば3つの判定が通り、行末の空白を落として写した2行（`ねじ\t12\nばね\t5`）が「行末の空白を除く」段で見つかることを確かめた（実測）。

## 実装前の仕様との違い

仕様の振る舞いは変えていない。仕様に書いていなかった細部は次のとおり。

| 点 | 実装 |
|---|---|
| ファイル | 行の分け方と行番号を付けた形を `read_file` から `tools/lines.py` に移し、`edit_file` と共に使う。下見と実行を `plan` から作る部品（`file_tool`）を `tools/file_change.py` に置いた |
| 結果の文を作る時 | `plan` が、書く前に結果の文を組み立てる（`FileChange.result`）。書いた後に返す |
| 2か所以上を置き換えた結果 | 行番号だけを並べ、前後の行は添えない |
| 字下げを直さない行 | 空の行と、`old_string` の共通の字下げで始まらない行は、そのまま置く |
| 行の単位の段の置き換え | 合った行の行末の空白は残らない |
| 最も近い所 | ファイルが `old_string` より短ければ、ファイルの全体と比べる。空のファイルは `ファイルは空である` |
| UTF-8 でない既存のファイル | `write_file` も書き換えずに誤りを返す（Claude Code の Write は、UTF-8 として書き直す） |
| 改行 | `\r\n` と `\n` が混ざったファイルは、どちらの道具でも書き換えずに誤りを返す。1つの改行に揃えて書くと、変えていない行の改行まで変わり、その変わりが差分に出ないためである |
| 末尾の改行の差分 | 末尾に改行が無い中身は、差分の最後の行の後に `\ No newline at end of file` を置く |
| 止めたときの表示 | 応答の後の1行を `（止めた）`・`誤り: …` に変え、その次の行に、履歴をどう扱ったかを出す |
| 下見の誤り | `confirmed` と `preview` は `null` |
