# F-01 チャットと走行の記録: 実装前の仕様

[作る機能](../../features.md) の F-01 の、実装の前に決めた仕様である。

## 何をするか

端末で依頼を打つと、手元の Ollama のモデルに送り、応答を流しながら表示する。モデルの API は会話の状態を持たないので、毎回、それまでの履歴の全体を送る。送った要求と受けた応答・トークン数・時間を、走行の記録（JSONL。1行に1つの JSON を書く形式）に残す。

この機能で確かめたいのは、会話の履歴を持っているのが API の側ではなく、呼ぶ側のプログラムだということである（[コーディングエージェントの仕組み](../../how-coding-agents-work.md#llm-は何をするか)）。

## 入力

- 起動: `.venv/bin/python -m local_coding_agent --model <モデルのタグ> [--host <URL>]`
  - `--model`: Ollama のモデルの名前（例: `qwen3.5:9b`）。必須
  - `--host`: Ollama の URL。既定は `http://localhost:11434`
- 端末で、依頼を1行ずつ打つ。空の行は無視する。Ctrl-D（入力の終わり）で終える

## 出力

- モデルの応答を、届いた順に端末へ流して表示する
- 応答が1回終わるたびに、数値を1行で表示する: 入力と出力のトークン数・最初の文字が届くまでの時間・全体の時間
- 走行の記録: 起動ごとに1つ、`traces/<起動の時刻>.jsonl` に書く。1行に1件で、要求と応答を交互に書く

| 件 | 中身 |
|---|---|
| 要求 | 時刻・何回目か・送った先の URL・送った JSON の全体 |
| 応答 | 時刻・何回目か・結果（終わった・止めた・誤り）・本文・終わった理由（`done_reason`）・Ollama が返したトークン数と時間・手元で測った時間（最初の文字まで・全体）・誤りの内容 |

## 振る舞い

- **会話の形**: 会話は Claude の Messages API の形で持つ。1つの発言は、役割（`user` か `assistant`）と、塊（content block）の並びである。F-01 で使う塊は本文（`text`）だけである。送る直前に、Ollama の `/api/chat` の形（役割と、本文の文字列）に変える
- **送るもの**: 毎回、それまでの履歴の全体に今回の依頼を足して、`/api/chat` に `stream: true` で送る
- **受け取り方**: 応答は NDJSON（1行に1つの JSON）で届く。1行ずつ読み、`message.content` を表示する。`done` が `true` の行で終わる。その行に Ollama のトークン数と時間（`prompt_eval_count`・`eval_count`・`total_duration` など）があれば、記録と数値の表示に使う
- **履歴に足す**: 応答が終わったら、今回の依頼と応答を履歴に足す
- **途中で止める**: 応答の途中で Ctrl-C を押すと、その回の応答を止める。その回の依頼と途中までの応答は、履歴に足さない。記録には、止めたことと途中までの本文を書く
- **誤り**: Ollama に繋がらないとき・誤りの応答（モデルが無いときの 404 など。本文は `{"error": "…"}`）が返ったとき・流している途中で `error` の行が届いたときは、内容を表示し、その回を履歴に足さずに、次の入力を待つ

## コードの置き方

| ファイル | 中身 |
|---|---|
| `local_coding_agent/__main__.py` | 引数を読み、REPL を起動する |
| `local_coding_agent/cli/repl.py` | 入力・表示・履歴 |
| `local_coding_agent/model/messages.py` | 会話の形（発言と塊） |
| `local_coding_agent/model/ollama.py` | 会話の形から `/api/chat` の形への変換・要求・NDJSON の読み取り |
| `local_coding_agent/trace/writer.py` | 走行の記録の書き出し |

HTTP は標準ライブラリの `urllib.request` で送り、応答を1行ずつ読む。

## テスト

`tests/` に、標準ライブラリの `unittest` で書く。実物のモデルにも、通信にも繋がない。

- 会話の形から `/api/chat` の形への変換
- NDJSON の読み取り（バイト列を渡す）: 本文の連なり・最後の行の数値・途中の `error`
- REPL: 決めた台本どおりに応答を返す偽物のモデルで、履歴が毎回全体で送られること・止めた回と誤りの回が履歴に入らないこと・走行の記録の中身

## 試し方

人が、手元の Ollama とモデルで試す。

1. 1回目に名前を伝え、2回目に「私の名前は？」と聞く。答えられれば、履歴が送られている
2. 走行の記録の2つ目の要求に、1回目の依頼と応答が入っていることを見る
3. 応答の途中で Ctrl-C を押し、次の回の要求にその回が入っていないことを見る

F-01 はコードを直せないので、`tasks/` の課題には掛けない。
