# 作る機能

このリポジトリで作る機能の一覧である。Claude Code の機能と、他のコーディングエージェント（Aider・OpenCode・Codex・OpenHands など）が持つ機能から選んでいる。用語の意味は [コーディングエージェントの仕組み](how-coding-agents-work.md) にある。

機能ごとの文書（実装前の仕様・実装した仕様・計測の結果・確かめる案内）は、`features/f-NN-<機能名>/` にある。

## 第1部 中核

ここまで作ると、小さな課題（失敗するテストを直す、など）をエージェントに解かせられる。

| # | 機能 | 何をするか | 作ると分かること |
|---|---|---|---|
| F-01 | チャットと走行の記録 | 端末で依頼を打ち、モデルの応答を流しながら表示する。毎回、履歴の全体を送る。要求と応答・トークン数・時間を記録する | API は会話の状態を持たず、履歴を持つのは呼ぶ側であること |
| F-02 | system prompt と環境の知らせ | モデルへの指示（役割・道具の使い方）と、作業ディレクトリや OS の知らせを組み立てる | 指示がどこから入るか。指示の長さが速さと守られ方にどう効くか |
| F-03 | 道具の呼び出しとループ | ファイルを読む道具を渡し、モデルが道具を呼ぶ間ループを回す。変更を伴う操作は、実行の前に人に確かめる | チャットとエージェントの違いが、道具の呼び出しとループにあること |
| F-04 | ファイルの書き込みと編集 | ファイルを書く道具と、文字列を置き換えて編集する道具。置き換え元が少し違う（空白など）ときに、段階的に緩めて探す | 編集の失敗が、内容の誤りと写し間違いのどちらで起きるか |
| F-05 | コマンドの実行と、結果を読んで直すループ | コマンドを走らせる道具。編集のあとにテストを走らせ、失敗を戻して直させる | 「確かめる」とは、コマンドの出力を道具の結果として読むことだ、ということ |
| F-06 | 許可 | 道具の呼び出しを、許す・確かめる・拒むの規則で判定する。全部確かめる・編集は通す・全部通す、のモードを持つ | 実行してよいかを決めるのはハーネスで、モデルは関わらないこと。規則の照合の限界 |

## 第2部

ここまでが最初の版である。

| # | 機能 | 何をするか | 作ると分かること |
|---|---|---|---|
| F-07 | slash commands | `/clear`・`/help` などの組み込みのコマンドと、ファイルに書いた手順を `/名前` で呼ぶ自作のコマンド | コマンドはハーネスが処理し、モデルに渡るのは中身の文だけであること |
| F-08 | skills | 手順書（スキル）の名前と説明だけを指示に入れ、モデルが選んだら本文を読み込む | 必要になったときだけ読み込むことで、文脈を使わずに多くの手順を持てること |
| F-09 | thinking | 推論を学習したモデルの推論を、`think` で入れたり切ったりする。前の回の推論の文を次の要求に戻すかを選べるようにする。推論の無いモデルでは、答えの前に推論を書かせる（手動の方式）。推論の文を受け取り、記録し、表示し、次の要求に戻すことは F-04 にある | thinking はモデルと API の機能で、ハーネスは受け渡しと表示をしているだけであること |
| F-10 | effort | 推論の強さ（low・medium・high）を選ぶ。あわせて、ハーネスの手間（道具の呼び出しの回数の上限など）を段ごとに変える | 手間の段階が、モデルの推論の量とハーネスの振る舞いのどちらにも掛けられること |

## 第3部 文脈と、小さいモデルの補い

| # | 機能 | 何をするか | 作ると分かること |
|---|---|---|---|
| F-11 | 指示ファイル | 作業ディレクトリの指示ファイル（AGENTS.md など）を読み、指示に入れる | 指示ファイルは強制力の無い文脈であること |
| F-12 | 文脈の要約 | 履歴が文脈窓の上限に近づいたら、古い道具の出力を削り、足りなければ会話を要約して入れ直す | 要約で何が失われるか。手元のモデルでは早く要ること |
| F-13 | checkpoint と巻き戻し | 道具を使うたびに作業ディレクトリの状態を別の git に保存し、指定の時点へ戻す | 巻き戻しの作り方の違い（ファイルの写しと git） |
| F-14 | plan mode | 計画の段では変更を伴う道具を渡さず、人が計画を承認したら実行の段に移る | 道具を渡さないことで、モデルの振る舞いを確実に縛れること |
| F-15 | タスクの管理 | モデルが作業の一覧を書いて更新する道具 | 長い作業で、モデルが進み具合を文脈に書き戻す意味 |
| F-16 | リポジトリの地図 | ファイルごとの定義（関数・クラス）の一覧を作り、文脈に入れる量を絞る | 探させるか、地図を渡すか。小さい文脈でどちらが効くか |
| F-17 | 失敗の繰り返しの検出と、完了の前の自己点検 | 同じ呼び出しと同じ誤りが続いたら止める。「終わった」と言ったら、差分とテストの結果を見せて確かめさせる | ループの歯止めをハーネスで作れること |

## 第4部 拡張と複数

| # | 機能 | 何をするか | 作ると分かること |
|---|---|---|---|
| F-18 | hooks | 道具の実行の前後とターンの終わりに、設定したコマンドを走らせ、結果で止める・続ける | 指示ではなく、決まった時点で必ず走る処理で振る舞いを決める仕組み |
| F-19 | subagent | 別の指示と道具の組で新しい会話を回し、要約だけを親に返す。並列にはしない | 文脈を分ける意味 |
| F-20 | MCP | MCP（道具をエージェントの外のサーバとして出す規格）のクライアントを作り、MCP サーバの道具を呼ぶ | 道具をハーネスの外に出す規格の中身 |
| F-21 | headless と、セッションの保存と再開 | 1回の依頼を引数で受けて結果を出して終わる形と、会話を保存して続きから再開する形 | 対話の画面とループが別の層であること |

## 作らないもの

- クラウドで動かす・スマホから操作するなど、Anthropic などのサービスに結び付いた機能（手元では同じものを作れない）
- web 検索（外部の検索サービスへの登録が要る）
- 並列の subagent・2つ目のモデルとの分担（メモリ 16 GB の機械では、モデルを2つ同時に載せる余地が乏しく、推論を並列にできない）
- エディタの中の補完・指示（このリポジトリで作るのは端末で動くもの）
