# コーディングエージェントの仕組み

コーディングエージェントは、LLM（大規模言語モデル）に、ファイルを読む・書く・コマンドを走らせるといった操作をさせるプログラムである。Claude Code はその1つで、このリポジトリはそれを手本にする。ここでは、作るものの全体像を説明する。

## LLM は何をするか

- LLM は、入力の文の続きを、トークン（語や語の一部などの断片）を1つずつ選んで足していくことで生成する
- LLM の API は会話の状態を持たない。2回目の質問をするときは、1回目の質問と答えを含めた**履歴の全体**を毎回送る。履歴を持っているのは、API を呼ぶ側のプログラムである
- モデルが一度に読める量には上限がある（文脈窓。トークン数で決まる）。履歴が長くなれば、いつか入りきらなくなる

## 指示（system prompt）

- 呼ぶ側のプログラムは、会話の先頭に、モデルへの指示を置く。これを system prompt と呼ぶ。役割・答え方・道具の使い方・守る規則などを書く
- system prompt も、会話のほかの部分と同じく文である。手元でモデルを動かす Ollama は、指示と発言の並びを、モデルごとの雛形（テンプレート）で1つの文に組み立ててから、モデルに渡す。モデルは、指示を、入力の文の先頭の部分として読む
- 指示は毎回の要求に入る。長い指示は、毎回の入力のトークン数を増やす
- 指示の入り口は system prompt だけではない。Claude Code は、作業ディレクトリ・OS などの環境の知らせと、指示ファイル（CLAUDE.md）を、system prompt ではなく会話の中に入れる。system prompt を変わらない文に保ち、キャッシュ（前の要求で処理した部分の使い回し）を効かせるためである

## 道具の呼び出し

LLM が出せるのは文だけで、自分ではファイルを読めず、コマンドも走らせられない。そこで、次の往復を行う。これを道具の呼び出し（tool use / function calling）と呼ぶ。

1. 呼ぶ側のプログラムが、道具の名前・説明・入力の形（JSON Schema）をモデルに渡す。例: `read_file`（入力は `path`）
2. モデルは、道具を使いたいときに、本文の代わりに「`read_file` を `{"path": "src/main.py"}` で呼びたい」という構造化した出力を返す
3. **プログラムが**その道具を実行し、結果（ファイルの中身）を履歴に足して、もう一度モデルを呼ぶ

モデルは道具を実行しない。実行するのは、いつも呼ぶ側のプログラムである。

呼び出しと結果は、どちらも履歴に入る。Claude の Messages API では、モデルの発言の中の `tool_use` の塊が呼び出しで、id・道具の名前・入力を持つ。1回の応答に、呼び出しが複数入ることもある。プログラムは、次の利用者の発言に `tool_result` の塊を入れて結果を返し、どの呼び出しの結果かを id で示す。道具が失敗したときや、入力が道具の定義に合わないときも、誤りの印（`is_error`）を付けた結果として返す。モデルは、それを読んで呼び直せる。

## エージェントのループ

エージェントは、モデルが道具を呼ぶ間、「モデルを呼ぶ → 道具を実行する → 結果を履歴に足す」を繰り返す。モデルが道具を呼ばずに本文だけを返したら、ループを終えて人に答えを見せる。

1. 人の依頼を履歴に足し、モデルを呼ぶ
2. 応答が道具の呼び出しなら、実行してよいかを確かめ、道具を実行し、結果を履歴に足して 1 のモデルの呼び出しへ戻る
3. 応答が本文だけなら、人に見せて終わる

コードを直すときは、たとえば「テストを走らせる → 失敗の出力を読む → ファイルを編集する → もう一度テストを走らせる」が、このループの中で起きる。

## ファイルの編集

モデルにファイルを直させる道具には、モデルに何を出力させるかで、主に2つの形がある。

| 形 | モデルが出力するもの | 例 |
|---|---|---|
| 丸ごと書く | 直した後のファイルの全体 | Aider の whole の形 |
| 置き換える | 直す所の今の中身（置き換え元）と、直した後の中身。ハーネスが、ファイルの中から置き換え元を探して置き換える | Claude Code の Edit・Aider の SEARCH/REPLACE（diff の形） |

丸ごと書く形は、数行の直しでもファイルの全体を出力させるので、遅く、出力のトークン数も多い。置き換える形は、変わる所だけを出力させれば済む。

置き換える形は、置き換え元がファイルの中身と合わないと失敗する。合わない理由は、モデルがファイルの中身を覚え違えたか（内容の誤り）、読んだ中身を写すときに空白や字下げを違えたか（写し間違い）である。写し間違いを補うために、比べ方を段階的に緩めて探すハーネスがある（Aider・Codex）。Claude Code の Edit は、そのままの一致だけで置き換える。

ファイルの変更は、実行してよいかを人に確かめる操作の典型である。書く前に差分を見せれば、人は何が変わるかを見て判断できる。

## コマンドの実行

モデルにシェルのコマンドを走らせる道具を渡すと、エージェントは、テストやビルドを走らせて、その出力を読める。直したコードが正しいかを決めるのは、モデルの見込みではなく、走らせたコマンドの出力である。モデルは、終了コードと出力を道具の結果として読み、失敗していれば、また直して走らせる。

- 道具の結果には、終了コードと出力（標準出力と標準エラー）を入れる。テストの失敗は、道具が失敗したのではなく、モデルが読む情報である
- 出力は長くなりうる。履歴に入れて毎回送るので、ハーネスは結果に入れる量に上限を置く。Claude Code の Bash は 30,000 字である
- コマンドは終わらないことがある（入力を待つ・無限ループ・サーバ）。ハーネスは時間を限り、過ぎたら止める。シェルが起こしたプロセスまで止めないと、残ったプロセスが動き続ける
- コマンドは何でもできるので、走らせる前に人に確かめる操作の典型でもある

テストを走らせる担い手には、2つの形がある。

| 形 | 走らせるのは | 例 |
|---|---|---|
| モデルが道具で走らせる | モデルが、走らせるかと、どのコマンドかを決める | Claude Code の Bash |
| ハーネスが編集のたびに走らせる | 利用者が決めたテストのコマンドを、ハーネスが編集の後に走らせ、失敗したら出力をモデルに返して直させる | Aider の `--auto-test` |

## 実行してよいかの判定（許可）

道具を実行してよいかは、ハーネスが決める。モデルは道具を呼ぶことを求めるだけで、その呼び出しが実行されるか・人に問われるか・拒まれるかを決められない。モデルが受け取るのは、実行した結果か、拒まれたことの知らせである。

ハーネスは、呼び出しを「通す・問う・拒む」のどれかに決める。決め方の部品は2つある。

| 部品 | 中身 | 例 |
|---|---|---|
| 規則 | 道具の名前と、呼び出しの形（パスやコマンドの型）ごとに、通す・問う・拒むを決める | `rm` で始まるコマンドは拒む。テストを走らせるコマンドは通す |
| モード | どの規則にも合わない呼び出しの決め方を、道具の種類ごとにまとめて切り替える | 全部問う・ファイルの編集は通す・全部通す |

Claude Code は、拒む規則・問う規則・通す規則の順に照らし、最初に合ったもので決める。規則は設定ファイルに書く。

規則は、呼び出しの文字列（パスやコマンド）に合わせるだけである。そのため、同じ操作を別の書き方で行えば、規則に合わない。

- `rm` で始まるコマンドを拒んでも、`find . -delete` や `python3 -c "import os; os.remove(...)"` でファイルを消せる
- テストを走らせるコマンドを通す規則は、テストのコード（モデルが書き換えられる）が行う全てを通す
- `safe && rm x` のように、許したコマンドの後ろにつないだものも通さないよう、Claude Code は複合のコマンドを分けてから照らす。それでも、Claude Code の文書は、コマンドの規則を安全の境界とはしていない

操作そのものを止めるには、OS のサンドボックス（プロセスが触れるファイルやネットワークを、OS が限る仕組み）が要る。Claude Code は、Bash の道具をサンドボックスの中で走らせることもできる。

## コマンド（slash commands）

端末で対話するエージェントの多くは、`/` で始まる行を、モデルへの依頼ではなく、ハーネスへの指示として扱う。これを slash commands と呼ぶ。Claude Code は、コマンドを行の頭でだけ認め、名前の後ろの文を引数にする。

| 種類 | ハーネスがすること | モデルに渡るもの | 例 |
|---|---|---|---|
| 組み込み | ハーネスの中の処理を行う（履歴を消す・設定を変える・一覧を出す） | 何も渡らない | Claude Code の `/clear`・`/help`・`/exit` |
| 自作 | ファイルに書いた手順を読み、引数を入れて、利用者の発言として送る | 引数を入れた手順の文 | Claude Code の `.claude/commands/<名前>.md` |

- 会話の履歴を持っているのはハーネスなので（[LLM は何をするか](#llm-は何をするか)）、`/clear` は、ハーネスが持つ履歴を空にするだけでできる。モデルの側では何も起きず、次の要求が短くなるだけである
- 自作のコマンドは、よく使う依頼の文に名前を付けたものである。ファイルを読むのも、引数を入れるのもハーネスで、モデルが受け取るのは、出来上がった文である
- Claude Code では、自作のコマンドは skills（下）にまとめられ、`.claude/skills/<名前>/SKILL.md` と同じに働く。本文の `$ARGUMENTS` が引数に置き換わり、置き換わる所が無ければ、末尾に `ARGUMENTS: <引数>` が足される

## スキル（skills）

スキルは、作業ごとの手順書（例: 変換を足す手順・レビューの観点）である。手順書を全て指示に入れると、使わない手順まで毎回の要求の入力に入る。そこでハーネスは、読み込みを3段に分ける。

| 段 | モデルに渡るもの | いつ |
|---|---|---|
| 一覧 | 全てのスキルの名前と説明（1つあたり数十から百トークンほど） | 毎回の要求 |
| 本文 | 選んだスキルの手順 | モデルが依頼に合うと判断して、読み込む道具を呼んだとき |
| 付いているファイル | スキルのディレクトリの中の、手順の細部・スクリプトなど | 本文を読んだモデルが、要ると判断したとき |

- どのスキルを使うかを決めるのは、モデルである。ハーネスは、一覧を見せ、呼ばれたら本文を返すだけで、依頼とスキルを照らし合わせない。説明の書き方が、選ばれるかを左右する
- 読み込んだ本文は、道具の結果（または利用者の発言）として履歴に入り、後の回でも送られる。毎回の要求に入るのは、一覧と、読み込んだスキルの本文だけである
- 利用者が名前で呼ぶこともできる。Claude Code では `/<名前>` で呼べ、自作のコマンド（上）と同じ打ち方になる
- Claude Code は、Skill の道具でスキルを呼ぶ。一覧の大きさに予算（文脈窓の 1%）を置き、超えると、使われることの少ないスキルから説明を落とす
- スキルのファイルの形（ディレクトリと `SKILL.md`、前付けの `name` と `description`）は、Agent Skills という規格として、Claude Code のほかのエージェントでも使われる

## ハーネスとモデルの分担

モデルの周りで、ループ・道具の実行・履歴の管理・許可の判定を受け持つプログラムを、ハーネス（harness）と呼ぶ。エージェントは、モデルとハーネスの組である。

| 担い手 | 受け持つもの |
|---|---|
| モデル | どの道具をどの引数で呼ぶか。どのスキルを読み込むか。編集で書き換える文字列。コードと説明の本文。答えの前の推論 |
| ハーネス | 指示（system prompt）と道具の定義の組み立て。スキルの一覧の組み立てと、本文の読み出し。履歴の保持と毎回の送信。道具の実行。実行してよいかの判定。ループの継続と終了。利用者のコマンドの処理。履歴が長くなったときの要約 |

Claude Code の機能の多くはハーネスの側にある。だから、モデルを自分で作らなくても、ハーネスを書けば仕組みの大半を確かめられる。このリポジトリでは、モデルにはローカル LLM を使い、ハーネスを自分で書く。
